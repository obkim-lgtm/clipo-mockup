## 0. 무엇이 바뀌나

### (1) 크레딧 — 차감 단위를 **인식(OCR) 기준 → AI 채점 기준**으로

### (2) 모델 — **시안3 하이브리드 폐기, 단일 경로로**
`인식 먼저 확인하고 채점` 갈래를 뺀다. 남는 흐름은 하나:

> **채점한다 → 결과가 이상하면 그 학생 인식 결과를 본다 → 고치면 재채점**

2026-07-06 하이브리드 채택 근거가 "인식 먼저 하면 재채점 크레딧 절약"이었는데, **크레딧 정책이 바뀌면서 그 근거가 사라졌다.** 상세는 §4-3.

| | 기존(2026-07-06 확정) | 변경(2026-08-26) |
|---|---|---|
| 차감 시점 | 인식 시 학생당 1회 | **AI 채점 시 학생당 1회** |
| 재채점 | 무과금(인식 재사용) | **1크레딧** |
| 인식·다시 인식 | 1크레딧 | **무과금** |

### 왜 바꾸나
- **직관** — "AI 채점 1회 = 1크레딧"이 고객이 이해하는 단위. 인식은 교사가 의식하는 작업이 아님.
- **기존 정책이 자기모순** — 시안3 하이브리드의 옵트인 문구가 `인식 결과를 먼저 점검해 재채점 크레딧 절약`인데, 인식당 과금이면 재채점이 애초에 무료라 절약할 게 없었음. 채점당으로 바꿔야 이 문구가 사실이 됨.
- **비인식 제출이 늘어남** — 직접 입력·설문(엑셀)·문항형 직접 제출까지 인식 자체가 없는 답안이 증가. 크레딧을 인식에 앵커하면 갈수록 어색해짐. (기존 구현도 직접 입력 학생에게는 채점 시 차감 — 이름만 인식당이고 실질은 학생당이었음)
- **UI 단순화** — 인식당 과금 때문에 채점 실행 2/2에 붙은 `사전 OCR` 컬럼과 "미리 한 M명은 추가 차감 없음" 각주가 전부 불필요해짐.

## 1. 확정 — 크레딧 차감 규칙

| 항목 | 결정 |
|---|---|
| 과금 단위 | **AI 채점 1회 = 1크레딧**, 학생 1명 기준(실행 버튼 1회 아님) |
| 부분 재채점 | 3명만 재채점 = 3크레딧 |
| 과제물 인식 | **무과금** — 최초·다시 인식 모두 |
| 재채점 | **1크레딧** — 인식 수정 후 재실행도 예외 없음 |
| 부분 제외 | 1문항이라도 AI가 채점하면 1크레딧 |

### 무과금 케이스 4종
| 케이스 | 근거 |
|---|---|
| AI 채점이 시스템 오류로 실패 | 결과를 못 줌. 이미 차감됐으면 복구 |
| 정확도 낮음으로 채점이 막힌 학생 | 채점 대상에서 제외됨 |
| 인식 실패 → 교사가 직접 채점 | AI가 한 일이 없음 |
| 전 문항을 `직접 채점(AI 제외)`으로 뺀 학생 | AI 채점 대상 0개 |

### 재채점 과금에 예외를 두지 않는 이유
"어떤 수정이 무료 재채점 대상인가"를 판정해야 하는데 그 경계는 설명이 불가능함.
대신 **무료 예방 경로**(`인식 먼저 확인하고 채점`)가 이미 있어 공정성 방어선이 성립.
단, **재채점 버튼·stale 배너에 차감을 반드시 표기**한다(숨은 과금이 최악).

## 2. 확정 — 학생 단위 `직접 채점`

교사가 인식 결과를 보고 "이 학생은 내가 직접 채점하겠다"를 선택할 수 있게 한다.
크레딧 절약이 목적이 아니라, **그 결정을 시스템이 기억하는 것**이 값어치.

### 구조 — 새 상태를 만들지 않는다
- 채점 상태 축은 **그대로**(미채점 → 완료). 학급 완료 판정도 안 건드림
- `AI 채점 제외`는 **상태가 아니라 표식(칩)**
- 학생 단위 토글 = **전 문항 토글을 한 번에 켜는 단축키**. AI 채점 여부는 항상 문항에서 파생(모순 상태 방지)

### 행동 → 결과
| 행동 | 결과 |
|---|---|
| 문항 1개만 제외 | 나머지는 AI 채점 → 1크레딧 차감 |
| 문항 전부 제외 | AI 채점 대상 없음 → 차감 없음, `AI 채점 제외` 칩 |
| `이 학생 직접 채점` 켬 | 전 문항 제외와 동일 → 차감 없음 |
| 다시 끔 | 전 문항 복귀 → AI 채점 대상으로 돌아옴 |

### 진입점 = 인식 결과 확인 화면 한 곳
- 근거: 인식 결과를 보고 판단하는 결정이므로 그 맥락에 있어야 함
- **크레딧 절약은 AI 채점 전에만 의미가 있음** → `바로 채점` 갈래에 이 선택지가 없는 것은 결손이 아니라 정합. (기존에 "하이브리드 비대칭"으로 지적했던 항목이 이걸로 해소됨)
- 해제도 같은 화면에서. 채점 실행 모달 비활성 행에는 `인식 결과에서 해제` 링크만

### 체크 해제와의 역할 분담
| 수단 | 위치 | 의미 | 다음 채점 실행 때 |
|---|---|---|---|
| 체크 해제 | 채점 실행 2/2 | 이번엔 안 함(일시) | 또 선택 대상으로 뜸 |
| `직접 채점` 토글 | 인식 결과 확인 | 앞으로도 AI 안 씀(영속) | 비활성 + 사유 `직접 채점` |

### 절약이 보이게
- 인식 결과 화면 — 토글 켤 때 "이 학생은 AI 채점에서 빠져요. 크레딧이 차감되지 않아요."
- 채점 실행 2/2 — 비활성 + 사유 `직접 채점`, 크레딧 N에서 제외

### 채점 화면 표현
인식 실패 케이스의 빈 화면을 **재사용**(점수 미체크 `- / 50` · AI 근거·피드백 숨김 · 선생님 직접 피드백 유지)하고 **사유 배너만 분기**.

| 케이스 | 문구 톤 |
|---|---|
| 인식 실패 | 우리 잘못 — "인식하지 못했어요, 원본을 보고 채점해 주세요" |
| 직접 채점 선택 | 교사 선택 — "선생님이 직접 채점하기로 한 학생이에요" + 해제 경로 |

기준 문서 [CLIPO 크레딧 정책 (26.07.29 FIX)](https://app.notion.com/p/3a417e5c8cf1805e9416cd36efaeac0d) 1장 (v0.7보다 최신본):

> CLIPO의 AI 기능(채점·기록 생성 등)을 **실행하면 학생 1명당 크레딧 1개**가 차감됩니다.

- 우리가 정한 "AI 채점 1회 = 학생 1명당 1크레딧"이 **이미 회사 기준 정책**
- 인식(OCR)은 차감 항목으로 문서에 등장하지 않음
- CLIPO 과제물 인식은 아직 **개발 전**이라 prod에 인식 차감이 존재할 수 없음
- → **공지·마이그레이션 불필요.** 거꾸로 2026-07-06의 "인식당 차감" 가정이 기준 문서와 어긋나 있었음(목업에만 존재한 가정)

### B 상세 — 기준 문서에 없는 빈칸 4개
문서는 "실행하면 차감"까지만 말하고 아래를 다루지 않음. 자연스러운 해석은 우리 결정과 같으나, CS 응대 기준이 되므로 차기 개정에 넣는 것이 좋음.

| 빈칸 | 우리 결정 |
|---|---|
| 재채점·재실행 시 차감 여부 | 차감 (1크레딧) |
| AI 작업이 시스템 오류로 실패했을 때 | 무과금·복구 |
| AI 채점이 막힌 학생(정확도 낮음 등) | 무과금 |
| 교사가 AI 채점을 뺀 학생·문항 | AI 채점 대상 0이면 무과금 |

### C 상세 — OCR 원가를 안고 가는 조건
인식 무과금으로 가면 **원가는 우리가 흡수**한다. 재인식은 꼬리 사건이라 안고 갈 만하다는 것이 결론이나, 무방비로 두지 않기 위해:

| 상황 | 원가 발생 |
|---|---|
| 재채점(파일 그대로) | 없음 — 저장된 인식 결과 재사용 |
| 파일 재업로드 | 발생 — 진짜 새 자료라 정당 |
| 인식 실패 → 다시 인식 | 발생 — 우리 잘못이라 흡수 |

과금 정책이 아니라 기술 처리라 고객 설명이 불필요. HIAI의 "변경 없으면 OCR 재사용" 정책과 결이 같음.

**⚠️ 검증되지 않은 전제**: 비용 분석에서 OCR/GCP 비용이 26년 5월부터 급증(건당 43배)한 신호가 잡혔으나, 그 수치는 *회사 전체 비용 ÷ CLIPO 사용량*이라 부풀려진 값이고 제품별 원가에서 CLIPO 몫만 떼는 재계산이 미완. "단가가 무시할 수준"이라는 전제가 아직 검증 안 됨 → 메모리 `project_clipo_cost_efficiency`

**판정선을 미리 긋기**: prod DB에서 학생당 실제 인식 횟수 분포를 뽑아 "평균 1.1회 이하면 안고 간다, 1.3회 초과면 재검토" 식으로 기준을 먼저 정하고 측정.

**알려진 구멍(막지 않음, 모니터링만)**: `인식 먼저 확인` → 채점 안 함 = 크레딧 0, 원가만 발생. 현재 크기는 무시 가능하나 답안 텍스트 추출 용도로 쓰이기 시작하면 커짐.

## 4-2. 확정 — 인식의 소유 화면 (점검 1, 2026-08-26)

**인식은 채점이 소유한다.** 과제물 관리는 제출 관리만 담당.

| 화면 | 인식 정보 |
|---|---|
| 과제물 관리 반 목록 | 없음 (현행 유지 — 이미 깨끗) |
| 과제물 관리 학급 상세 | **인식 칩 5종 · `인식 결과 확인 (N명)` CTA 제거.** 제출 축 칩(미제출/제출)만 유지 |
| 채점 | 인식 상태·결과·수정·실패 대응 전부 |

### 근거
- **`바로 채점`이 기본이면 과제물 관리의 인식 칩은 거의 항상 "미진행"** — 인식은 채점 실행 시점에 돌기 때문. 칩 5종을 깔고 한 칸만 켜지는 구조였음
- 2026-07-06 결정(뱃지 복잡도 회피 · 인식은 단일 홈)이 여전히 유효
- 인식 축이 두 화면에 있으면 라벨·색·집계 동기화 부담 + 교사가 "어디서 고치지?"를 매번 판단해야 함

### 대가와 대응
채점 전에 "우리 반 과제물이 읽을 만한가"를 미리 보는 경로가 없어짐 → 그것이 곧 `인식 먼저 확인` 옵트인의 존재 이유이므로 별도 제공하지 않는다(제공하면 옵트인이 무의미).

**⚠️ 선결 조건**: 인식 실패 시 **채점 화면에서 그 자리에서 `파일 다시 올리기`가 가능해야 한다.** 현재의 "과제물 관리에서 확인" 안내로 넘기면 원칙만 지키고 교사가 길을 잃음.

## 4-3. 확정 — `인식 먼저 확인` 갈래 제거 (점검 2·3, 2026-08-26)

### 전제가 된 사용자 행동 (올립 관찰)
> 교사가 채점 전에 과제물을 훑는 습관이 있는 과제도 있지만, **한두 명 보고 괜찮으면 다 OK하고 채점**한다. **채점이 이상할 때 인식 결과를 본다.**

훑는 대상은 **과제물 원본**이지 인식 결과가 아니다. 이 흐름 어디에도 "채점 전에 인식 결과를 본다"가 없다.

### 이 갈래가 막아주는 손실이 거의 없다
`인식 먼저 확인`의 유일한 명분은 "채점 크레딧을 쓰기 전 무료 미리보기". 그런데 무과금 규칙 확정 후:

| 인식이 나쁜 경우 | 크레딧 |
|---|---|
| 인식 실패 | 채점이 막힘 → **무과금** |
| 정확도 낮음 | 채점 대상 제외 → **무과금** |
| 읽히긴 했는데 틀리게 읽힘 | 차감 — **그러나 인식 먼저 봐도 전수 확인해야 발견되므로 이 기능이 못 막음** |

→ 진짜 사고(전멸)는 이미 무과금으로 걸러지고, 남는 케이스는 이 기능으로도 막지 못한다.

### "불안하면 미리"는 이미 되고 있다
채점 실행에서 **1명만 골라 채점**(1크레딧). 채점 결과까지 보므로 인식만 보는 것보다 확실하고, 새로 만들 기능이 없다.

### 없어지는 것
- 채점 실행 모달의 `채점 방식` 세그먼트 (`rm-seg`·`rmMethodField`·`rmSetMethod`·`applyRunModalMode`)
- 인식 진행 모달 3단 (`ocrFirstModal` stage1~3) · `백그라운드로 진행` · `나중에 확인`
- 채점 목록 학급 칸 인식 상태머신 (`setCellOcrState`: running/review) · 재진입 플래그 (`ocrEntryViaCell`·`ocrCtxCell`)
- 인식 결과 화면 하단 `선택 학생 채점 · N명` / 동적 back 라벨
- 2/2의 `사전 OCR` 컬럼 (크레딧 결정으로 이미 제거 대상)

### 살아남는 것 — 시안2로 되돌아가는 것이 아니다
시안3에서 얻은 자산은 유지하고 **진입 시점만 "채점 후"로 통일**한다.
- 인식 결과 확인 화면과 케이스(정상·확인 필요·정확도 낮음·인식 실패)
- 문항 단위 `직접 채점 (AI 제외)` 토글 + 학생 단위 직접 채점
- 인식 상태 사전(라벨·색)
- 되돌리기·수식 입력·저장 후 다음

> ⚠️ **재검토 필요**: 케이스 중 `인식 진행 중`은 인식이 채점에 묶이면서 사실상 "채점 중"과 같아진다. 별도 케이스로 남길지 §5에서 판단.

### 4 — 인식 결과 화면 안쪽 구조

#### ✅ 확정 — 인식 결과는 채점 상세 안에서만 본다 (`screen-ocr-b` 폐기)

채점 상세는 **2층 구조**이고 이대로 유지한다. 진단과 교정에 필요한 대조 대상이 다르기 때문.

| 상황 | 좌측 | 우측 |
|---|---|---|
| **진단** — 점수가 왜 이상하지? | `인식 결과` 탭 | 채점 결과(점수·근거) |
| **교정** — 인식을 고치자 | `원본 제출물`로 자동 전환 | 드로워(문항 카드·편집) |

`과제물 인식 결과 수정`(`openOcrEdit`) → 좌측이 원본으로 자동 전환되어 대조 가능. 이미 구현돼 있음.

**`screen-ocr-b`를 접는 근거**
- 갈래 제거로 들어갈 문이 없어짐
- 안의 문항 카드·되돌리기·수식·직접 채점 토글이 **이미 드로워에 이식돼 있어 중복**
- "채점 이상하면 그 학생 하나를 본다"는 행동에 학생 순회용 큰 화면이 불필요

**사라지는 것**: `screen-ocr-b` 화면 전체 · 학생 드롭다운 · 하단 바 · 순회용 `저장 후 다음` · 관련 라우팅

**케이스별 화면**

| 케이스 | 좌측 | 우측 | 드로워 |
|---|---|---|---|
| 정상 | 인식 결과 | 채점 결과 | 열림 |
| 확인 필요 | 인식 결과 + 불확실 표시 | 채점 결과 | 열림 |
| 정확도 낮음 | 원본(인식 결과 숨김) | 직접 채점 | 불필요 |
| 인식 실패 | 원본 | 직접 채점 | 대신 `파일 다시 올리기` |

#### ✅ 확정 — 화면 안 내용 (2026-08-26)

> **원칙 (올립)** — CLIPO도 HIAI와 **같은 모델·같은 정보 표시**가 기본. 다르게 가려면 근거가 있어야 한다.
> 흐름은 갈라졌지만(§4-3) **화면에 보여주는 정보의 구성은 통일**한다.

| 항목 | 결정 | 근거 |
|---|---|---|
| `풀이 (그림/도형/표)` | **수정 불가**로 전환 (🔒 · 회색 박스). 편집·되돌리기·수식 버튼 제거 | 전사가 아니라 **AI의 해석**. 고치면 그것이 곧 채점 행위가 되고, 그 문장을 누가 썼는지 흐려짐. 애매한 문항은 `직접 채점 (AI 제외)`가 정확한 처리 |
| Layer1/Layer2 분리 | **가져오지 않음** — 한 덩어리 | HIAI는 수학·과학 특화 구조. CLIPO는 전과목 |
| `풀이·답만 보기` 토글 | **가져옴** | 정보 표시 통일 원칙. 드로워에 축약명과 전체 지시문이 둘 다 표시돼 접을 분량이 있음 |
| 인식 수정 저장 | **명시 저장 버튼** (드로워 하단). **blur 자동저장 제거** | ⚠️ HIAI와 의도적으로 다름 — HIAI는 채점 **전**에 고치니 저장에 결과가 없지만, CLIPO는 채점 **후**라 저장이 곧 **재채점 유발**. 확정 시점이 명확해야 함 |
| 채점 저장 | 현행 유지(저장 버튼) | HIAI와 이미 동일 |
| 재채점 버튼 | **크레딧 차감 표기** | 숨은 과금 방지 |

### 5 — ✅ 확정 — 상태 축 (2026-08-26)

#### 인식 상태 8종 → 3종
갈래 제거로 나머지는 **발생 자체를 하지 않는다**(정보 표시 통일 원칙의 예외가 아니라 사실의 문제).

| 인식 상태 | CLIPO 단일 경로 |
|---|---|
| 미진행 | 발생 안 함 — 채점 안 하면 인식도 없음 = `미채점` |
| 진행 중 | `AI 채점 중`에 흡수 |
| 완료 | `채점 완료`에 흡수 |
| 미확인 | 발생 안 함 (검수 비의무) |
| **확인 필요** | 남음 — 채점됐으나 인식 불확실 |
| **정확도 낮음** | 남음 — 채점 막힘 |
| **인식 실패** | 남음 — 채점 막힘 |

남는 3종은 전부 **채점 결과 칸의 사유**로 표시. 별도 인식 열은 만들지 않음(포팅 스펙 §2-2와 동일).

#### `확인 필요` 라벨 충돌 해소
현재 `scoring_elementary_v3` 한 파일에서 같은 라벨이 두 뜻으로 쓰임(12곳+).

| 위치 | 현재 | 변경 |
|---|---|---|
| 학생 목록·헤더 (채점 축) | `확인 필요` | 유지 — AI 점수 검토 |
| 드로워·전사 문항 칩 (인식 축) | `확인 필요` | **`인식 불확실`로 교체** |

HIAI가 이미 같은 방식으로 해소함. **라벨 전수 교체는 목업 작업 시 grep으로 처리**(올립 2026-08-26).

#### 인식 실패 대응 = 채점 화면에서 버튼 2개
진행 모달이 없어지면서 "재시도 → 성공 / 또 실패" 불일치는 자동 해소(남는 곳이 한 군데).

| 버튼 | 성격 | 크레딧 |
|---|---|---|
| `다시 인식하기` | 보조 — 일시 오류용 | 무과금 |
| `파일 다시 올리기` | 주 — 품질 문제용 | 무과금, 이후 재채점 시 1 |

파일 교체 결과는 **과제물 관리 제출 정보에도 반영**되어야 함.

### 6 — ✅ 확정 — 문항형 직접 제출과의 정합 (2026-08-26)

인식 결과는 **요청만 통으로, 결과는 문항별**(올립 확인) → 문항별 카드 구조 유지.

제출 방식 세 갈래 중 인식이 필요한 것은 하나뿐.

| 제출 방식 | 인식 |
|---|---|
| 직접 입력(문항별 타이핑) | 불필요 |
| 파일 제출 | **필요** |
| 설문 응답(엑셀) | 불필요 |

#### 직접 입력 학생의 채점 상세 좌측
현재 `method:'typing'` 학생 5명(정현우·한지우·임도윤·김도현·노유찬)에게 **다른 학생의 공통 정적 답안이 표시됨** = 가짜 데이터 → [[feedback_mockup_no_fake_data]]

- **이번엔 플레이스홀더로**: `직접 작성 제출 내용 나옴` 정도로 표시 (올립 — **디자인 피그마 나오면 그때 반영**)
- 탭 스위처 불필요(원본 파일이 없어 전환 대상 없음)
- `과제물 인식 결과 수정` 버튼 **숨김** — 2026-07-06 "숨기지 말고 비활성+안내" 원칙은 *일시 상태*(미채점) 기준. 직접 입력은 영구히 인식이 없어 비활성 버튼이 헛된 기대를 만듦

#### 문항 변경(추가·수정·삭제) → 인식·채점 연쇄 = **이번 범위 밖**
PRD v0.3이 제출 후 문항 추가·수정·삭제를 허용하나, **그 처리는 문항 기능이 소유**한다(올립 2026-08-26). OCR은 인식 결과만 다룬다.

> 📌 **이관** — 삭제·이관이 아니라 트랙 이동. 문항 변경이 인식 결과·채점 결과에 미치는 영향은 [[project_clipo_direct_write]] 쪽에서 다룬다. HIAI가 같은 문제를 3분류(추가=미연결 / 삭제=연결 소멸 / 지시문 수정=확인 필요)로 이미 풀었으므로 그때 참고. **문항 단위 부분 재채점 가능 여부**(크레딧이 학생 단위라 충돌)도 그 트랙에서 개발 확인.

## 6. HIAI 확정본과의 격차 (정합 여부 보류)

HIAI OCR은 디자인·개발 완료 후 **QA 단계**(2026-08-26 기준) → 그 화면이 개발 확정본.
CLIPO OCR은 2026-07-29 이후 정지. 그 사이 HIAI가 확정한 것:

- 전사 텍스트 카드형 + `풀이·답만 보기`
- 인식 실패 빈 화면 · 재채점 배너
- 학급 상세 상태 컬럼 정의
- 저장 축 분리(인식=자동저장 / 채점=저장 버튼)
- 채점 실행 확인형 다이얼로그(3단계 진행 모달 폐지)
