> 작성 Olivia. '활동지로 바로 채점' 목업 작업 중에 "당장 개발이 어려우니 이 기회에 홈도 리뉴얼하자"로 커졌다. 목적이 달라서 새 세션으로 분리한다.

## 1. 왜 홈을 다시 짜나 — 진단편 근거
- 문제 정의 덱: `../../clipo_problem_definition/` (`context.md` · `클리포 문제정의_260925.pptx`). 숫자 출처 = `../../clipo_traffic_analysis/context.md` §3.999b.
- **P1 진입**: 인증 교사 60%가 30일 안에 채점을 안 함. 재방문 이탈의 80%는 수업 만들기 이전. 설계까지 하고 멈춘 교사(재방문 539명)는 81%가 교사 일괄 업로드를 골랐고 58%는 다시 와서도 안 올림 → **올리는 단계가 벽**.
- **P2 정착**: 실반 첫 채점자의 38%가 점수를 저장하지 않음(원인은 인터뷰 필요).
- **P3 발견**: 학생 제출 사용 교사 8%, 결과 공개 과제 5%, 기능 문의 38%가 '어떻게·어디서'. 안 쓰이는 기능은 전부 '평가 설계의 선택지'.
- **홈 온보딩 배너 투어 시작률 30% → 12%** — '들어올 때 알리기'는 효과가 없음. 안내는 행동하는 자리에서.
- 올립이 추가로 풀고 싶은 것(09-25): **업데이트된 기능을 사용자가 모름** · **연수(무료, 끝까지 참여 시 AI 크레딧 200개 쿠폰)를 모름** · 블로그(채점 예시·가이드 영상) 노출을 높이고 싶음.

## 2. 정해진 방향
- **할 일 중심.** 올립: "내가 뭐 하면 될지, 할 거 중심으로." '수업 목록 + 할 일 띠를 덧붙인 것'은 여전히 목록 중심이라 탈락.
- **수업 카드 = 그 수업의 '다음 할 일' 하나 + 버튼**(초안에 구현). 수업에 붙은 일은 수업 카드에서(올립: "수업 카드에 넣어서 수업 연계되는 게 더 낫다").
  - 다음 할 일 사다리: 시작 전(평가 만들기) → 답안 기다림(스캔 PDF 올리기 · 학생 제출로 받기) → 채점 → 확인 필요 → 결과 공개 전(결과 공개하기) → 세특. P1·P2·P3의 행동 지점이 카드 위에 그대로 뜬다.
  - 카드 위쪽은 개발 카드 그대로(이름·⋮ 메뉴), '수행평가 N개 · 과목'은 작은 한 줄.
- **수업이 없는 일**(새 입구의 임시 채점 · 채점기준 초안)은 수업 카드에 못 붙는다 → 자리 필요.
- 새 기능 알리기의 문법(다른 서비스 공통): ① 기능 자리의 `New` 배지 + 첫 사용 때 한 줄 ② 행동 순간의 제안 ③ 제품 안 '새 소식' 모음 ④ 제품 밖(메일·블로그 소식). 피하는 것 = 로그인 팝업·캐러셀·긴 투어. CLIPO는 학기 리듬이라 **"지난 학기 이후 달라진 것"**으로 묶는 게 맞다. 필요하면 실제 화면으로 벤치마크 조사해서 다시 바꾼다(확인된 것만 해결편에).
- 블로그 쪽 결정(`../../clipo_blog/context.md` §7): 홈 오른쪽 자료실 첫 카드 → 블로그 배우기 탭. 진짜 주목도는 기능 화면 안의 맥락 링크. 상단바 고정 영역엔 넣지 않는다.

## 3. 초안에서 해 본 것 · 올립 반응
| 해 본 것 | 반응 |
|---|---|
| 온보딩 배너 자리에 '새로 시작'(활동지로 바로 채점 + 과목별 채점 예시 링크, 임시 채점이면 이어보기로 바뀜) | **"좀 그렇다"** — 다시 생각할 것. 새 세션의 첫 과제 |

| 오른쪽 레일: 지난 학기 이후 달라진 것([써 보기]·[확인했어요]) · 공지사항 · 연수 카드(이벤트 카드 자리) · 클리포 블로그 한 장 | 레일이 "너무 많다" → 학교 정보·자료실 뺐음. 유튜브는 갱신 안 하니 블로그 소개로. 달라진 것+공지사항 합치기는 미정 |
| 채점기준 화면에 블로그 영상 맥락 링크(R1 채점기준 잘 쓰는 법 2:26) | 흐름 목업에 남겨 둠 |

## 4. 새 세션에서 정할 것
1. **새 입구·임시 채점의 자리**(온보딩 배너 자리는 반려). 후보: 현재 학기 그리드 첫 칸 카드(흐름 목업에 쓰는 안) / 수업 카드 사다리의 '0번 칸' / 기타.
2. 수업 카드 사다리를 보여 줄 데이터 — 한 교사에게 수업 3~4개를 두고 단계별로? (가짜 데이터 늘리는 것이라 올립 확인 필요 — 메모리 `feedback_mockup_no_fake_data`)
3. 한 수업에 평가가 여럿일 때 어떤 할 일을 띄울지(제안: 마감 가까운 것 → 멈춘 지 오래된 것).
4. 오른쪽 레일 최종 구성(달라진 것 · 공지 합치기 여부, 연수 카드가 이벤트 자리를 써도 되는지 — 다른 팀 캠페인 일정 확인).
5. 체크리스트·개인정보 동의서 양식을 블로그 '학교 도입 자료'로 옮길지.
6. 기존 사용자 영향 — 홈은 모든 교사의 첫 화면이다. 덱의 "기존 화면은 그대로" 약속이 바뀌므로 해결편에 근거를 다시 쓴다.
