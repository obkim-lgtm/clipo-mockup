### 1-3. 새 메뉴 위치·이름

- **위치 = `수업 관리` 그룹, `자동 채점` 바로 위**(올립 지정). 파이프라인 순서(인식 → 채점)와 메뉴 순서가 일치한다.
  - HIAI는 `과제물 검수`(전처리) 바로 아래였다. **CLIPO엔 전처리 화면이 없어 기준점이 다르다** — 근거가 "전처리 다음"이 아니라 "채점 앞"으로 바뀐 것.
- **이름 = `인식 결과 검수`** ✅ 올립 확정 2026-09-10.
  - 같은 그룹 라벨이 `수행평가 설계`·`자동 채점`·`세특`·`제출 파일`로 전부 짧은 명사구라 평행성을 맞춘 것([[feedback_label_parallelism]]). HIAI 명칭 `OCR 인식 결과 검수`는 이 줄에서 혼자 길어 쓰지 않는다.

### 1-4. 목록 화면 관례 — **신형(`쿠폰 관리`)을 따른다**

⚠️ CLIPO Admin에는 **목록 패턴이 두 가지 공존**한다. 아무거나 베끼면 안 된다.

| | 구형 (`staffs/records` 제출 파일) | **신형 (`쿠폰 관리`) ← 이걸 따른다** |
|---|---|---|
| 필터 | 입력칸 3개 + 파란 `조회` 버튼 | **칩 + 드롭다운 + 검색**, 카드로 감쌈 |
| 목록 헤더 | 없음 | **`쿠폰 목록 총 25개`** |
| 셀 | 평문 | **뱃지**(유형·상태) |
| 행 액션 | `자세히` 텍스트 링크 | **outline 버튼** (`이용 현황`) |
| 페이저 | `‹ 1 2 3 4 5 … 56 ›` | (캡처에 안 잡힘 — 착수 시 확인) |

신형이 **HIAI 검수 목업과 거의 같은 뼈대**다. 칩·총건수·뱃지가 이미 있으니 새 패턴을 들이는 게 아니다.

**신형 레이아웃 (쿠폰 관리 그대로 옮길 것)**

```
☰  CLIPO Admin                                   김옥빈님 접속 중 ⌄
─────────────────────────────────────────────────────────────────
쿠폰 관리                                        [+ 새 쿠폰 생성]
정액제·종량제 쿠폰을 생성하고 이용 현황을 확인합니다.

┌ 필터 카드 ───────────────────────────────────────────────────┐
│ [전체] [정액제] [종량제] [만료]                                │
│ (모든 유형 ⌄) (모든 코드 유형 ⌄) (전체 상태 ⌄) [검색…      ] │
└──────────────────────────────────────────────────────────────┘

┌ 목록 카드 ───────────────────────────────────────────────────┐
│ 쿠폰 목록 총 25개                                             │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 헤더행(회색 배경) … 뱃지 셀 … [이용 현황]                 │ │
└──────────────────────────────────────────────────────────────┘
```

- **페이지 헤더** = 타이틀 + 설명 한 줄 + 우측 상단 primary 버튼. 검수 화면엔 생성 버튼이 없으니 **우측 버튼 자리는 비운다**(억지로 채우지 말 것).
- **칩** — 활성은 파란 채움/흰 글씨, 비활성은 흰 배경 + 회색 테두리. HIAI 검수의 `전체/미판정/Fail/의견 있음/…`을 그대로 이 모양으로.
- **뱃지 색 관례** (그대로 재사용): 파랑 연한 = 분류(`공용 코드`) / 주황·초록 연한 = 유형(`종량제`·`정액제`) / 빨강 연한 = 종료 상태(`만료`).
  → 검수에서는 `Pass` 초록 · `Fail` 빨강 · `미판정` 회색.
- **행 액션** = outline 버튼. HIAI 목업은 행 전체 클릭 + `›`였는데, CLIPO는 **버튼을 쓰는 쪽이 관례**다.
- 숫자 컬럼은 가운데 정렬([[feedback_table_center_alignment]]).

**학생명** — 구형 목록은 `김채O`로 마스킹하지만, **`인식 결과 검수`는 목록·상세 모두 실명으로 표시한다** ✅ 올립 확정 (§2-2).

**푸터** — 이용약관 / 개인정보처리방침 / © 2026 Datadriven Inc.

## 2. CLIPO 고유 — 그대로 못 옮기는 것

### 2-1. 전처리 단이 통째로 빠진다 ✅ 올립 확정

**CLIPO엔 비식별화가 아직 없다.** 원본 과제물을 그대로 불러온다고 보면 된다.

빠지는 것:
- 상세 상단 **전처리 요약 줄** (`자동 회전 완료 · 비식별화 완료`)
- **전처리 검수 메모 N건** 표시 + `전처리 상세` 링크
- 상태·정책 규칙 2행(`전처리 요약 표시`·`전처리 검수 메모`)
- 비범위 2행(`과제물 검수` 화면 변경 · 회전·비식별화 전처리 정책)
- 좌측 컬럼 이름: `비식별화된 과제물 원본` → **`과제물 원본`**

결과적으로 상세 세로 흐름이 4단 → **3단**: `선생님 의견 → 인식 결과(2단) → 하단 판정 바`

### 2-2. 학생 실명 노출 ✅ 올립 확정

**과제물 원본은 가공 없이 그대로 띄우고, 학생명도 목록·상세 전부 실명으로 표시한다**(올립 2026-09-10).

- CLIPO Admin 구형 목록은 `김채O`로 마스킹하지만 **`인식 결과 검수`는 따르지 않는다.** 어차피 손글씨 원본에 이름·학번이 그대로 보이므로, 목록만 가리는 것은 형식적일 뿐이고 검수자가 원본과 목록의 학생을 대조하기만 어려워진다.
- HIAI는 비식별화가 이름을 가려서 애초에 생기지 않던 갈림길이다. **CLIPO는 비식별화가 없으므로 "가린다"는 선택지 자체가 성립하지 않는다.**
- 참고: CLIPO는 열람 로그가 없다([[project_hiai_deidentification]]). 즉 **로그 없이 실명으로 본다.** 내부 관리자 전용 화면이라는 전제가 이 결정의 근거이므로, **접근 권한이 운영자 계정으로 제한되는지는 구현 시 확인**할 것.

### 2-3. `정확도 낮음` 케이스가 CLIPO엔 없다

26-09-04에 **케이스 자체를 삭제**했다(최유진 명단 제거). 크레딧이 차감되는데 결과를 감추면 안 되기 때문 ([[feedback_paid_result_visibility]]). 불확실 문항이 많아도 `인식 불확실`로 흡수한다.

따라서 HIAI PRD에서 **통째로 빠지는 것**:
- 상태·정책 규칙 `정확도 낮음 — 선생님 화면`(결과 숨김·AI 채점 제외) / `— 검수 화면`(숨겨진 건 안내)
- QA 점검표·시나리오의 70% 관련 항목
- 검수 상세의 "선생님 화면에서는 숨겨진 건" 배너

**남기는 것**: 목록의 `확인 필요` 3구간 색 구분(0% / 1~69% / 70%↑). 라벨이 아니라 **운영자가 열어볼 순서를 정하는 장치**라 CLIPO에서도 유효하다.
- 단 `정확도 낮음` **필터 칩은 이름을 바꿔야 한다** — 그 상태가 CLIPO에 없으므로. 후보: `확인 필요 많음`.

### 2-4. `다시 인식` 버튼이 없다 — 회차 개념을 다시 정의해야 한다

HIAI 교사 화면엔 `다시 인식` 버튼이 있어서 "인식 결과 1:N 누적 → 목록 1행 = 인식 결과 1건 = 검수 1건"이 자연스러웠다. **CLIPO엔 그 버튼이 없다.** 재인식이 도는 경로는:
- **파일 교체** (송하림 케이스) → 새 파일로 OCR 재실행
- `다시 채점` — 채점만 다시 돌리는 것이라 인식 회차와 무관

**✅ 올립 확정 2026-09-10 — 행 단위는 HIAI 그대로, 라벨만 CLIPO 사실에 맞춘다.**

**단위 정의 (이 한 줄이 규칙 전부다)**

> **한 번의 제출(파일 1~N개) → 인식 결과 1건 = 목록 1행 = 판정 1건.**
> 파일을 교체해 다시 인식이 돌면 **새 행**이 생기고, 이전 행의 판정은 그대로 남는다.

| | 결정 |
|---|---|
| 파일이 여러 개일 때 | **행이 갈리지 않는다.** 상세에서 **파일 드롭다운**(`10101_김하나.pdf  2 / 4 ⌄`)으로 전환 — 교사 화면과 **같은 컴포넌트를 그대로 쓴다** |
| 판정 단위 | **제출 1건 = 판정 1건.** 파일 3장 중 1장만 나쁘더라도 "이 학생 과제물의 인식 품질"이라는 하나의 판단 |
| `확인 필요` 비율 | 파일별로 쪼개지 않고 **제출 전체의 문항 기준으로 합산** |
| 회차 뱃지 | `2차`·`3차` → **`교체 후`**. `다시 인식` 버튼이 없으므로 `N차`는 사실이 아님 |
| 필터 칩 | `다시 인식` → **`과제물 교체`** |
| 상세 회차 이동 | **유지.** 라벨은 `1차 보기`/`2차 보기` → **`교체 전 보기`/`교체 후 보기`** |

**근거**
- 판정 단위와 행 단위를 맞추면 규칙이 가장 단순하다는 HIAI 근거가 CLIPO에서도 그대로 성립한다.
- 교사 화면이 이미 파일을 드롭다운으로 묶어 **한 학생의 과제물 하나**로 보여준다. 백오피스가 파일 단위로 쪼개면 교사가 보는 단위와 검수 단위가 어긋나 의견·판정을 어디에 붙일지가 흐려진다.
- ✅ **줄리 시안이 `다시 인식` 부재를 확증한다** — 인식 실패·레거시 화면의 CTA가 전부 `다시 채점`이다(§2-7).

> ⚠️ 교체가 2번 이상이면 `교체 후`만으로는 구분이 안 된다. `인식 일시`로 갈리므로 뱃지는 그대로 두되, 목업에서 3건 이상 케이스를 만들어 실제로 읽히는지 확인할 것.
> ⚠️ "판정 단위"·"비율 합산"은 올립이 파일 드롭다운을 확인해 준 데서 이어 붙인 것이다. 착수 시 한 번 소리 내어 확인할 것.

### 2-5. 크레딧 축 (HIAI엔 없다)

CLIPO는 채점당 1크레딧, 인식은 무과금([[project_clipo_ocr_inline]]). **모델 테스트에 크레딧 규칙을 명시해야 한다** — HIAI PRD엔 이 문장이 아예 없다.

- **모델 테스트는 교사 크레딧을 차감하지 않는다** (관리자 행위, 회사 비용). 이 한 줄을 PRD 상태·정책 규칙에 넣을 것.
- HIAI의 "호출 비용이 있으므로 명시적 실행" 근거는 CLIPO에서도 그대로.

### 2-6. Beta 표기 자리 — 붙일 컬럼이 CLIPO엔 없다 ✅ 올립 확정

HIAI는 **학급 과제물 목록의 `과제물 인식` 컬럼 헤더**에 Beta를 붙였다. **CLIPO엔 그 컬럼이 없다** — 확인한 결과:

| 화면 | 컬럼 |
|---|---|
| 학급 채점 현황 (`class_scoring_detail_v1_260512`) | 이름 · 학번 · 채점 상태 · AI 점수 · 최종 점수 · AI 채점 결과 · 학생 채점 |
| 과제물 관리 (`task_ocr_v3_260623`) | No. · 이름 · 학번 · 제출 파일 · 최근 제출 일시 · AI 채점 · 선생님 채점 · 상태 · 관리 |

인식 상태가 독립 컬럼 없이 `AI 채점`·`상태`에 흡수돼 있다.

**결정 — 인식 결과가 실제로 노출되는 곳에만 붙인다. 목록에 컬럼을 새로 만들지 않는다.**

⚠️ **자리는 줄리 시안(§2-7)을 보고 확정한 것으로 갱신됨.** CLIPO의 인식 결과는 **채점 상세 좌측 패널의 `인식 결과` 탭**에 있다. 별도 팝업이 아니다.

```
10101_김하나.pdf  2/4 ⌄  ⊘ AI 채점 제외   03/21 14:00 업로드      [⤓ 다운로드]
┌──────────────────────────────────────────┐
│ [📄 제출 원본] [🗐 인식 결과]  ← 다크 탭바  │   ← ⭐ Beta 표기·`알려주기`는 여기
└──────────────────────────────────────────┘
```

- **Beta 표기** = `인식 결과` 탭 옆 (탭 라벨에 붙이거나 탭바 우측)
- **안내 박스 + `알려주기`** = `인식 결과` 탭을 켰을 때 결과 위. **탭 콘텐츠 바깥·탭바 바로 아래**에 둘 것 — HIAI에서 박스를 결과 패널 바깥에 둔 덕에 인식 실패·빈 상태에도 같은 자리에 붙어 케이스 분기가 필요 없었다. 안쪽에 넣으면 케이스마다 분기를 짜게 된다.
- **`제출 원본` 탭에는 붙이지 않는다** — 원본은 AI 산출물이 아니다.

> HIAI는 **좌 원본 / 우 인식 결과 2단**인데 **CLIPO는 좌측 패널 하나에서 탭 전환**이다(우측은 채점 패널이 차지). 교사 화면 레이아웃이 근본적으로 다르니 HIAI 교사 목업을 레이아웃 기준으로 삼지 말 것. **백오피스 검수 화면은 별개 화면이라 2단 유지.**

### 2-8. Beta 표기·의견 수집 **대상이 아닌** 케이스

HIAI는 `OCR 미실시` 하나만 제외했다. **CLIPO는 네 가지다** — 전부 "AI가 읽은 결과가 없다"가 공통 이유.

| 케이스 | 이유 |
|---|---|
| **직접 입력**(`.txt`) | 학생이 타이핑한 원문. OCR을 거치지 않음 |
| **AI 채점 불가**(`.hwp` 등) | 인식 대상 파일이 아님 |
| **미제출** | 좌측 패널 자체가 없음 |
| **레거시** | 인식 기능 이전에 채점된 건. 인식 결과가 존재하지 않음 |

**대상인 케이스** = 인식 성공 / 인식 불확실 / **인식 실패**(HIAI와 동일하게 의견 수집 대상 — 반복 실패 제보가 개선 가치가 가장 크다).

> ⚠️ 레거시는 판단이 갈릴 수 있다. "다시 채점하면 볼 수 있어요"라 아직 인식 결과가 없을 뿐이므로 **표기·의견 모두 빼는 쪽**으로 뒀다. 다시 채점하면 그때 대상이 된다.

## 3. 그대로 가는 것 (재검토 불필요)

HIAI PRD에서 근거까지 확정돼 CLIPO에서도 성립하는 항목:

- **Beta 표기는 인식 결과가 노출되는 화면마다, 의견 수집은 한 곳만** — 창구가 갈리면 데이터가 흩어짐
- **의견 = 유형 복수 선택 + 자유 의견** (유형 6종). 자유 의견만 받으면 유형별 빈도를 못 셈
- **인식 실패 건도 의견 수집 대상** — 시스템은 "이번에 실패"까지만 알고, 반복 실패로 못 쓰고 있다는 건 교사만 안다
- **OCR 미실시는 제외** — 화면 진입 자체가 안 됨
- **같은 인식 결과에 여러 번 제보 가능**, 중복 차단 없음
- **의견은 단방향 제보** — 상태·회신 없음
- **판정 = Pass / Fail / 미판정 3값**, Fail은 사유 필수
- **판정 1:N 이력** — 목록은 최신 판정, 상세에서 이전 판정까지. 하단 판정 바는 **열 때 항상 비움**
- **모델 테스트는 덮어쓰기(이력 없음) · 관리자 공용 · 두 축 모두 현재 모델이면 실행 불가**
- **테스트 인식 결과는 판정 대상 아님** — 서비스되지 않는 결과를 판정하면 집계가 오염됨
- **상세 기본 2단 → 모델 테스트 시 3단**
- 정렬 기본값 = 미판정 우선 → 확인 필요 비율 내림차순
