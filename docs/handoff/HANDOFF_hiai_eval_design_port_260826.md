## 1. 두 시안 (확정 전)

갈림길은 **"AI가 제대로 채점할지를 무엇으로 판단하나"**.

| | 시안1 `evaluation_design_v5.html` | 시안2 `evaluation_design_v6.html` |
|---|---|---|
| 판단 근거 | 채점 전 **적합성 진단**(AI 판정) | **실제 채점 결과**(답안 1장 미리 채점) |
| 흐름 | 설계 → 진단 ① 채점기준 연결 ② 적합도 진단 | 설계 → 저장 팝업 → 미리보기 채점 → 다듬기 → 저장 전 시험 채점 → 확정 |
| 판정 표기 | `다시 볼 곳 있음` / `바로 채점 가능` | 판정 없음 — 점수를 직접 보여 줌 |
| 채점기준 수정 | AI 제안 → 적용 | AI 제안 → **시험 채점으로 확인 후** 확정 |

### 어느 쪽이 확정돼도 공통 (지금부터 준비 가능)
1. **설계 화면 = 그룹 카드 2개** — `기본 설계`(5항목: 기본 정보·성취기준·채점기준·점수 계산 방식·결시자 처리) + `AI 채점 정확도 개선 (선택)`(빈 활동지 등록·채점 가이드·모범답안). 좌측 목차 없음, 세로 스크롤 한 화면.
2. **빈 활동지(문제지) 등록이 설계 안으로** 들어온다. 파일 카드 → 문항 구조 확인, 단 구분 없는 한 화면.
3. **문항 ↔ 채점기준 연결**을 교사가 문항별로 고칠 수 있다. AI가 먼저 연결하고 교사가 수정(좌 문항 목록 / 우 체크박스 좌우 분할).
4. **AI 제안 채점기준**을 작업본으로 편집 후 적용.
5. **잠금 2축 유지** — 과제물 인식 후(참조 축) / 채점 실행 후(값 축).

## 2. ⚠️ CLIPO 고유 충돌 — 이식 전 결정 필요

포팅이 단순 리스킨이 **아닌** 지점 셋. 시안 확정 시 함께 정해야 한다.

### 2-1. CLIPO엔 이미 진단이 있다 — 단, 지금은 보류 상태
- CLIPO는 `scoring_diagnosis_v1_260616.html`로 **모범답안 기반 채점 진단**을 만들어 뒀고 PRD(`C-AI 채점 진단`)도 있다.
  - 구성: 진입 모달(모범답안 = 파일 업로드 / 학생 제출물 중 선택 2택, `진단 1회 · AI 크레딧 1개 차감` 표기) → 분석 중 팝업(창 닫으면 취소) → **진단 리포트 모달** = ① 채점기준별 판정 배지 **`적합`(초록)/`주의`(주황)** + `예상 N/M점` + 개선 제안 ② AI 채점 수준 제안(`모범답안 예상 점수 16/20점` → 채점 시 점수 수준을 더 높게)
  - 후속 액션: 리포트 하단 `채점기준 수정` → `evaluation_design_v4`로 이동
- **✅ 다행히 지금은 꺼져 있다** — 현행 세트 `task_ocr_v3`에서 진단 버튼이 `display:none`(주석 `다음 배포까지 숨김`), 프로모 배너는 `HANDOFF_ocr_credit_policy_260826.md` §7에서 제거 대상, `service_overview.md`도 2학기 타깃 미반영으로 분류. **`docs/design-system.md` 개발 확정 화면 표에도 없다**(= 확정 화면 아님).
- 따라서 **충돌은 덜 첨예하다.** 시안2가 확정돼도 "이미 나간 기능을 회수"하는 게 아니라 **보류 중인 기획을 흡수·대체**하는 셈. 다만 PRD가 살아 있으니 문서 정리는 필요하다.
  - **시안1 확정 시** → 기존 진단을 2단(연결 → 적합도)으로 개편 + 판정 표기 교체(`적합`/`주의` → `바로 채점 가능`/`다시 볼 곳 있음`). 모달 중심 → 화면 중심 전환이 추가 작업.
  - **시안2 확정 시** → 기존 진단 기획을 **폐기·흡수**하고 PRD를 정리. 병존은 권하지 않음(같은 질문에 답하는 기능이 둘).
  - 어느 쪽이든 **살릴 만한 자산**: "AI 채점 수준 제안"(모범답안 예상 점수로 점수 수준을 조정하라는 가이드)은 HIAI 시안 둘 다에 없는 CLIPO 고유 아이디어 — 버리기 전에 검토.
- 관련 메모리: `project_scoring_diagnosis`

### 2-2. ~~CLIPO는 활동지가 별도 탭~~ → 해소 (2026-08-28 올립)
- **활동지 탭은 제품에 안 들어간다** — `question_tab_v1_260617.html`은 목업으로만 만든 것이라 없앨 예정. 충돌 자체가 사라짐.
- 따라서 **① 설계 안으로 흡수(HIAI와 동일)로 확정** — 빈 활동지 등록·문항 정의는 평가 설계가 소유. 2026-08-26 확정("과제물 양식 업로드는 과제물 관리에서 제외 → 설계 쪽에서 푼다")과도 일치.
- 후속 계획: **내년(2027) "문항 탭"** — 문항을 생성해주는 AI — 로 별도 진입. 그때 설계와의 관계(생성기 → 과제물 공급)를 다시 정의. 활동지 탭 목업 자산은 재활용용으로 보존(`context_question_tab.md`).

### 2-3. 크레딧 (HIAI엔 없는 축)
- CLIPO 현행: **AI 채점 1회 = 1크레딧, 학생 1명 기준**(실행 버튼 1회 아님). 인식(OCR)은 무과금, **재채점도 예외 없이 차감** — `docs/handoff/HANDOFF_ocr_credit_policy_260826.md`.
- 무과금 4종: 시스템 오류 실패 / 정확도 낮음으로 막힌 학생 / 인식 실패 후 직접 채점 / 전 문항 `직접 채점(AI 제외)`.
- **미리보기도 학생 1명이니 규칙대로면 1크레딧.** 시안2는 한 번 개선하는 데 채점이 최소 2회(미리보기 + 시험 채점) 돌고, 다듬기를 반복하면 계속 늘어난다. 여기에 **`채점기준 AI 생성` 드로워도 크레딧을 소모**하고 기존 **진단도 1크레딧**이라, 설계 한 건에 붙는 크레딧이 누적된다.
- 정해야 할 것: ① 미리보기 차감 여부 ② 시험 채점 차감 여부 ③ 차감한다면 **재채점처럼 버튼·밴드에 차감을 명시**(숨은 과금 방지 원칙).
- 유료 정책과 직결 → **확정 전엔 목업에 크레딧 표기를 넣지 말 것.**
- 관련 메모리: `project_clipo_credit_policy`

### 2-4. 기존 AI 생성 드로워와 어긋나는 두 지점
CLIPO엔 이미 **`채점기준 AI 생성` 드로워**가 확정·배포돼 있다(2026-08-04, `evaluation_design_v4` `#rubAiDrawer`). 시안의 다듬기와 **같은 화면에 공존**하게 되므로 아래 둘을 맞춰야 한다 — 안 맞추면 한 화면에서 AI가 채점기준을 주는 방식이 두 가지로 갈린다([[feedback_ui_consistency]]).

| | 기존 드로워 (확정) | HIAI 시안2 다듬기 |
|---|---|---|
| **적용 방식** | 카드 **선택형** → `채점기준 적용하기 (n)` → 목록에 **추가**(덮어쓰기 아님) | 작업본 통째로 **덮어쓰기**(`이 채점기준으로 바꾸기`) |
| **창을 닫으면** | **생성 계속됨**(X·바깥 클릭 막지 않음, `[중지]`만 명시적 취소). 안내도 중립 문구 | **"이 화면을 벗어나면 처음부터 다시 해야 해요"**(이탈 경고) |

- **적용 방식**: 시안2의 덮어쓰기는 "시험 채점으로 확인한 세트를 확정"하는 것이라 성격이 다르긴 하다. 다만 교사 입장에선 같은 화면의 AI 기능 둘이 하나는 추가·하나는 교체라 혼란 소지. → 다듬기 결과도 선택형으로 갈지, 덮어쓰기를 유지하되 문구로 구분할지 결정 필요.
  - 참고: HIAI도 `채점기준 세트 교체는 제품에 없음`(26-08-04) → 진단 재구성안은 `일괄 적용 + 덮어쓰기`(26-08-21)로 갈렸던 이력이 있음.
- **이탈 처리**: 기존 드로워는 이미 "닫아도 계속"으로 확정했는데 시안2 다듬기는 이탈 경고를 쓴다. **CLIPO에서는 드로워 쪽에 맞추는 게 맞다**(이미 확정된 동작 + 3분 대기를 붙잡아 두지 않음). 다듬기 로딩 문구를 CLIPO용으로 바꿔야 함.
- 기존 드로워 참고 사양: 생성 1~2분(길면 3분) · 진행 메시지 **순환 4종 5초**(순차·✓완료는 폐기 — 단일 파이프라인이라 시스템이 단계를 모름, [[feedback_system_honest_signaling]]) · 완료 알림 없음.
- 기존 드로워 미결(그대로 승계): 닫았다 다시 열면 결과가 남는지 **개발 확인 필요** · **PRD 미작성**.
- 관련 메모리: `project_clipo_rubric_ai_drawer`

## 4. 시안2 이식 사양 (확정 시 이대로)

> 시안1이 확정되면 이 절 대신 `evaluation_design_v5.html` 구조를 따른다(진단 2단 = 연결 → 적합도, 판정 `다시 볼 곳 있음`/`바로 채점 가능`).

### 4-1. 설계 → 미리보기 유도
- 저장하면 **토스트 + 목록으로 이동** → 목록에서 **일회성 팝업** 노출.
- 팝업 조건: 평가명 + 채점기준 + **채점 가이드**가 모두 있을 때만(미리보기가 돌 수 있는 상태). 잠김·채점 완료·이미 미리보기를 써 본 평가는 제외.
- 상시 배너는 **쓰지 않는다** — 미리보기는 저장된 설계로 도는데 저장 전 노출은 "수정 중인 내용으로 채점해 준다"로 읽힌다([[feedback_ui_state_data_truth]]).
- 상시 인지는 **목록 카드의 `채점 미리보기` 버튼**이 담당(작성 중 제외).

### 4-2. 미리보기 화면 (풀 페이지 좌우 분할)
- 상단 바: 뒤로(진입 경로 따라 `목록으로`/`설계로`) · 파일명 · `다른 답안으로` · `다시 채점`.
- 답안 1장 드롭존 → 로딩(**3분 안내 + 이탈 경고**) → 결과.
- 좌: 원본 제출물 / 인식 결과 세그먼트 — 공통 지시문·문항별 학생 답안·시각자료.
- 우: 총점+등급 · 채점 결과(배점 칩, AI 선택 강조) · AI 채점 근거 및 피드백(과제물 분석 AI / 루브릭 기반 AI 탭).
- **CLIPO는 실제 채점 화면 구조를 따를 것** — `class_scoring_detail_v1_260512.html`. (HIAI는 Figma `MM23uA7pDEmFeMKGeFVJpB` `1752:7372`에서 이식했음)

### 4-3. 채점기준 다듬기 (탭 2개)
- 진입 시 **AI 분석 로딩** 먼저(제안 채점기준 + 문항 연결 생성). 재진입은 로딩 없이 편집으로, 새 답안을 올리면 처음부터.
- **AI 진단 의견** = 기준별 카드가 아니라 **한 덩어리 글**. 연결이 문제면 연결을 보라 하고, 기준이 문제면 고쳐 쓴 안을 제안.
- 탭 A `채점기준` — AI 제안 작업본(수정·추가·삭제·복제).
- 탭 B `문항 연결` — 좌 문항 목록(`기준 n개`/`미연결`) / 우 지시문 + AI가 고른 이유 + 체크박스. `모두 선택`/`모두 해제`.
- **채점기준 개수가 바뀌면 AI가 연결을 그 자리에서 다시 만들고** 안내 배너 표시. 저장 전이라 확인 단계 없음.
- 하단 CTA `이 설정으로 채점해 보기` — 저장하지 않고 시험 채점.

### 4-4. 시험 채점 결과 → 확정
- 결과 상단 밴드: `[아직 저장 전]` + `지금 쓰는 기준으로는 12/20점(D)이었어요`.
- 버튼 3개(순서 고정): **`이 채점기준으로 바꾸기`**(primary) / `채점기준 다시 수정`(outline) / `원래 기준 그대로 두기`(ghost).
- `바꾸기` → **확인 다이얼로그 없이 즉시 적용**(그 기준으로 채점한 결과를 보고 누르는 버튼이므로) → **설계 상세의 채점기준 섹션으로 이동** + 토스트.
- 교사가 정한 문항 연결을 그대로 저장. 연결 탭을 안 거쳤으면 AI 자동 연결(끊긴 채로 저장하지 않음).
- `원래 기준 그대로 두기` → 작업본 비우고 **들어온 곳으로 이동**(다시 채점해 보여 주지 않음).

## 5. 확정 카피 (그대로 사용)

| 위치 | 문구 |
|---|---|
| 저장 팝업 제목 | `AI 채점 결과를 미리 테스트해 보시겠어요?` |
| 저장 팝업 본문 | `AI가 채점한 결과를 보고 선생님 의도대로 채점하는지 확인해 보세요. 생각과 다르게 나왔다면 AI와 함께 채점기준을 고칠 수 있어요.` |
| 저장 팝업 버튼 | `나중에` / `AI 채점 미리보기` |
| 드롭존 제목 | `답안 한 장으로 미리 채점해 보세요` |
| 드롭존 본문 | `지금 설계로 AI가 어떻게 채점하는지 볼 수 있어요.` + `채점 결과는 저장되지 않고, 학생 점수에도 반영되지 않아요.` |
| 다듬기 로딩 | `채점 결과를 보고 채점기준을 다시 쓰고 있어요` ⚠️**뒷문장은 CLIPO에서 교체** — 기존 드로워가 "닫아도 계속"으로 확정돼 있어 이탈 경고를 쓰면 안 됨(§2-4). 시간도 미확정 |
| 연결 탭 설명 | `문항마다 볼 채점기준을 AI가 골라 뒀어요. 왼쪽에서 문항을 고르고, 맞지 않으면 체크를 바꿔 주세요.` |
| 재연결 안내 | `채점기준을 고쳐서 문항 연결을 다시 만들었어요.` + `AI가 새로 연결한 결과를 확인하고, 맞지 않으면 고쳐 주세요.` |
| 미연결 안내 | `연결하지 않아도 괜찮아요. 이 경우 이 문항은 채점기준 전체로 채점돼요.` |
| 시험 채점 CTA | `이 설정으로 먼저 채점해 볼까요?` + `아직 저장하지 않아요. 고친 채점기준과 문항 연결로 같은 답안을 채점해 보고, 결과가 마음에 들면 그때 바꾸면 돼요.` |
| 확정 토스트 | `채점기준을 바꿨어요. 문항 연결도 새 기준으로 다시 만들었어요.` |
| 되돌리기 토스트 | `원래 채점기준을 그대로 뒀어요.` |

> **톤 주의(루카스)**: "우리 AI에 맞춰 평가를 바꿔라"로 읽히지 않게. 마지막 문장은 `AI와 함께`처럼 도와준다는 쪽으로.
