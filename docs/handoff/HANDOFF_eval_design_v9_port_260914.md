## 1. HIAI v9에서 확정된 것

### 1-1. 설계의 구조
- **설계 = 채점기준까지 입력하면 완료.** 그 위에 선택 흐름 **`AI 채점 정확도 높이기` 3단계** — ① 빈 활동지·문항 확정 ② 문항별 채점기준 연결(매트릭스) ③ 모범답안·채점 가이드. 되돌아가기 O, 건너뛰기 X.
- **채점기준 AI 검토** — 맥 API `{ grade: 우수|적절|보완필요, comment }`. 전체 루브릭 단위 한 번. 채점기준 섹션 아래 배너 한 자리에서 끝남. 막지 않고 안내만, 고치면 결과가 낡았다고만 알림.
- 채점기준 카드에 **`연결 문항` 행**(칩 + `변경`/`문항 연결` → ②단).
- **설계 문항은 과제물 인식(OCR)과 연결되지 않는다** — 채점 때 참고하는 맥락 정보. 과제물 화면의 문항 구분은 따로 나뉨.
- **연결 없는 문항·연결 없는 채점기준은 둘 다 AI 채점에서 제외**(v1.0 "미연결 문항은 채점기준 전체로 채점" 폐기).

### 1-2. 고친 뒤 처리 — 초기화하지 않는다, 지운 것만 지운다 (26-09-08 개발 회의)
| 바꾼 것 | 결과 |
|---|---|
| 채점요소 제목·배점·세부기준 수정 | 아무것도 안 지워짐 |
| 급간 삭제 | 그 급간으로 매긴 점수만 삭제, 학생은 `확인 필요` |
| 채점요소 삭제 | 그 요소의 연결·점수만 삭제, 학생은 `확인 필요` |
| 채점요소 추가 | 미연결로 들어옴, 아직 채점 전이라 학생은 `확인 필요` |
| ① 문항 추가·삭제·수정 | ②③ 초기화 없음(새 문항 미연결, 지운 문항 것만 제거) |
| 활동지 교체·재분석 | 문항·연결·모범답안만 새로. 인식·채점 결과는 유지 |

- `일부 채점` 태그는 따로 두지 않는다 — 기존 `확인 필요` 하나. (빌은 "미채점(일부 채점)"이라 불렀지만 태그는 `확인 필요`로 정리)
- 사전 안내 배너·초기화 확인창·잠금 없음.

### 1-3. 채점 후 저장 선택창 (26-09-10 최종)
**뜨는 조건**: 채점된 학생이 있고 **채점기준을 지웠거나 새로 넣었을 때만.** 제목·배점·세부기준만 고쳤으면 창 없이 저장 → 토스트 `수정되었습니다.`

**모양**: Basic_Modal(좌측 정렬 제목 + X 닫기). 한때 개발 화면 모양(가운데 정렬·X 없음)으로 맞췄다가 피그마 Basic_Modal로 되돌림.

| 자리 | 문구 |
|---|---|
| 제목 | 이미 채점한 학생이 있어요 |
| 본문 | 지금 점수는 고치기 전 채점기준으로 매긴 거예요. 점수를 지우면 바뀐 기준으로 다시 채점하고, 유지하면 고친 기준이 지금 점수에 반영되지 않아요. |
| 회색 ⓘ 줄 · 지움만 | 지운 채점기준으로 매긴 점수는 유지해도 사라져서 그 학생은 확인 필요로 표시돼요. |
| 회색 ⓘ 줄 · 추가만 | 새로 넣은 채점기준은 아직 채점 전이라 그 학생은 확인 필요로 표시돼요. |
| 회색 ⓘ 줄 · 둘 다 | 지운 기준으로 매긴 점수는 유지해도 사라지고 새로 넣은 기준은 아직 채점 전이라 그 학생은 확인 필요로 표시돼요. |
| 질문 | 점수를 어떻게 할까요? |
| 버튼 | `점수 지우고 저장`(보조, 왼쪽) · `점수 유지하고 저장`(주, 오른쪽) |

이 문구에 오기까지 버린 것 — CLIPO에서 같은 실수를 반복하지 않게:
- **본문과 버튼의 단어·순서를 맞춘다.** 본문의 "지우면 → 유지하면"이 왼쪽 → 오른쪽 버튼 순서와 같다. `그대로 두면` ↔ `유지하고`처럼 뜻이 같아도 단어가 다르면 매핑 비용이 든다.
- **"지우다"가 두 대상에 겹치지 않게.** 채점기준을 지우는 행위(원인)와 점수를 지우는 선택(버튼)이 한 창에 있어서, 선택 쪽엔 반드시 `점수를`을 붙인다.
- **질문 줄은 버튼으로 넘기는 다리**(올립). 선택지를 되풀이하지 않고 무엇을 정하는지(`점수를`)만 짚는다.
- **원인은 회색 줄, 선택은 본문·버튼.** 추가는 선택을 바꾸는 사건이 아니라 알려줄 사실이다.
- 케이스별로 나눌 거면 **원인은 케이스마다 정확하게, 결론(`확인 필요로 표시돼요`)만 같게.**
- 학생별 상세·인원 수 없음. 빨강 없음. `되돌릴 수 없어요` 없음.

### 1-4. 헤더 문구 (26-09-09)
- 목록: `진행할 평가를 설계해 주세요. 설계한 내용은 과제 제출 방식과 AI 채점의 기준이 됩니다.`
- 상세: `성취기준과 채점기준을 정하면 설계가 완료됩니다. AI 채점 정확도 높이기까지 마치면 채점 결과가 더 정확해집니다.`
- 목록은 "무엇의 기준이 되나", 상세는 "어디까지 필수·어디부터 선택". HIAI 형제 탭에 맞춰 격식체.

## 2. CLIPO에서 그대로 성립하지 않는 것 (사실 확인된 차이)

| # | 차이 | 근거 | 왜 문제인가 |
|---|---|---|---|
| A | **`확인 필요` 라벨이 이미 다른 뜻** | `clipo_mockup/context.md` 330행 — `확인 필요` = AI 채점 실패 후 교사 확인, 빨강 | HIAI 뜻(설계 변경으로 점수가 일부 빠짐)을 그대로 쓰면 한 라벨이 두 사건. 색도 빨강이라 과한 경고가 됨 |
| B | **점수를 지우면 크레딧이 든다** | AI 채점 1회 = 학생 1명당 1크레딧, 재채점도 예외 없이 차감(`HANDOFF_ocr_credit_policy_260826.md`) | HIAI의 `점수 지우고 저장`은 공짜 선택이지만 CLIPO에선 다시 채점하는 순간 학생 수만큼 차감. 선택창이 비용을 말하지 않으면 숨은 과금 |
| C | **인식은 채점이 소유** | 옛 핸드오프 §3 치환표 — CLIPO 과제물 관리 = 제출 관리만 | HIAI "설계 문항은 OCR과 무관"·"활동지 교체해도 인식 결과 유지"의 화면 위치가 달라짐 |
| D | **이미 있는 AI 기능 둘** | `evaluation_design_v4_260615.html` `#rubAiDrawer`(채점기준 AI 생성, 확정·배포) · `scoring_diagnosis_v1_260616.html`(진단, 보류) | HIAI `채점기준 AI 검토`·`AI로 다시 연결`이 같은 화면에 붙으면 AI가 채점기준을 다루는 방식이 여럿. 옛 핸드오프 §2-1·§2-4 |
| E | **HIAI API가 CLIPO에 있는지 모름** | 맥 채점기준 검토 API·문항 연결 API는 HIAI 기준으로만 확인됨 | 없으면 1-1의 검토 배너·②단 AI 연결 전제가 무너짐 |
| F | **자동저장 없음** | 메모리 `feedback_clipo_no_autosave` | 선택창이 저장 버튼에서만 뜨는 구조는 맞음 — 차이라기보다 확인 |

## 3. 새 세션에서 정할 것 (올립)

**먼저 "좀 다르게"의 축을 한 줄로 정하면 나머지가 따라온다.** 후보:
1. **범위를 줄인다** — 정확도 높이기 3단계 없이 "고친 뒤 처리"만 가져간다 (CLIPO에 연결 API가 없으면 자연스러운 선택)
2. **순서를 바꾼다** — 크레딧 때문에 "점수 지우기"를 선택창에서 빼고 다른 자리로
3. **모델은 같고 표기만 다르다** — HIAI 규칙 그대로, 라벨·문구·크레딧 표기만 CLIPO식

그다음 결정 목록:

| # | 질문 | 관련 차이 |
|---|---|---|
| 1 | 설계 변경으로 점수가 일부 빠진 학생을 CLIPO에서 뭐라고 부르나 — 기존 `확인 필요`와 합칠지, 새 라벨인지 | A |
| 2 | 저장 선택창에 `점수 지우고 저장`을 둘지. 둔다면 크레딧을 어디에 어떻게 말할지 (지울 때는 무과금, 다시 채점할 때 차감 — 이 구분을 창에서 말할지) | B |
| 3 | 채점요소 **추가**만 해도 학생 상태가 바뀌는 걸 CLIPO에서도 같게 볼지 (크레딧: 새 요소만 채점하는 부분 재채점이 있는지) | A·B |
| 4 | AI 채점 정확도 높이기(활동지·연결·모범답안)를 이번에 넣을지 | C·E |
| 5 | 기존 `채점기준 AI 생성` 드로워·보류 중인 진단과 HIAI `채점기준 AI 검토`의 관계 | D |
| 6 | 선택창 모양 — CLIPO 모달 컴포넌트(`docs/design-system.md`) 기준. HIAI Basic_Modal을 따를 이유는 없음 | — |

**하지 말 것**
- CLIPO API·크레딧 동작을 추정해 목업에 박지 말 것 — 개발 확인 전엔 질문으로 남긴다([[feedback_dev_domain_questions]]: 구현 how는 묻지 말고 결과 규칙만 올림).
- HIAI 문구를 복사하기 전에 "CLIPO에서도 성립하나"부터([[feedback_hiai_reference_only]]).
- 옛 핸드오프 §4~§6 사양을 되살리지 말 것.
