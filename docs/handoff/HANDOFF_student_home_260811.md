## 2. 확정 정책 (올립 확정 — 시안 5도 이 정책을 따른다)

### 노출 원칙
학생에게 보이는 건 **선생님이 학생에게 "연" 것뿐**. 교사의 업로드·채점 활동은 결과 공개 전까지 학생 화면에 나타나지 않는다.

| 케이스 | 결과 공개 전 | 공개 후 |
|---|---|---|
| 교사 수거형 (학생 제출 안 엶) | **학생 홈에 아무것도 없음** | 결과 나온 과제 |
| 학생 제출형 · 온라인 제출 | 제출이 끝난 과제 | 결과 나온 과제 |
| 학생 제출형 · 종이로 내서 교사가 대신 업로드 | 제출이 끝난 과제 | 결과 나온 과제 |
| 교사가 결과를 공개하지 않음 | 그 자리 그대로, 채점 기색 없음 | — |

- 교사 수거형 비노출의 이유 = **선생님 혼자 클리포를 쓰는 사용 방식을 침해하지 않기 위함.** 이게 CLIPO의 원조 사용 방식이다.
- 학생 제출형은 **교사가 등록하면 즉시** '곧 시작하는 과제'에 노출(제출 시작일 안내). 상세 진입은 불가.

### 섹션 배치 규칙
- 마감 지남 + 아직 제출 가능 → **'지금 낼 과제' 맨 위** (정렬 = 남은 시간 오름차순, 지난 건 음수)
- 마감 지남 + 제출 불가 → **'제출이 끝난 과제'에 미제출 칩**
- 마감 없음 → '지금 낼 과제' 맨 아래

### 문구 원칙
- **"선생님 확인 중" 금지.** 결과 공개는 교사 선택이라 안 올 수 있다 → 지킬 수 없는 안내가 된다. 그래서 섹션명이 '제출한 과제'가 아니라 **'제출이 끝난 과제'**(미제출도 담기므로)이고, 설명은 "결과는 선생님이 **공개하면** 볼 수 있어요".
- **점수는 공개된 건에만** 표시. 교사가 `hide-score`로 끌 수 있음(`output/result_student_view_v3_260512.html`에서 확인). 비공개를 '비공개'라고 적지 않는다 — 박탈감만 준다.
- '제출 없이 채점' 같은 **교사 관점 용어 금지** → '선생님 등록'.

### 화면 구성 원칙
- 섹션 순서 = **학생 목적 순**: 지금 낼 과제 → 결과 나온 과제 → 제출이 끝난 과제 → 곧 시작하는 과제
  (상태 진행 순으로 두면 액션 없는 '제출이 끝난 과제'가 2번 자리를 차지함)
- **액션이 있는 것만 카드**(지금 낼 과제), 보기만 하는 건 행
- 모든 목록 섹션 **5개 + 더 보기**

## 3. 기각한 대안 — 재론 방지 (실측 근거 포함)

| 안 | 기각 이유 |
|---|---|
| 수업 필터 **가로 스크롤** | 1줄 54px로 아끼지만 **230px 분량이 화면 밖**. 데스크톱(min-width 1180px)에서 휠이 세로라 접근 불가. 모바일 패턴을 잘못 가져온 것 |
| 수업명 **말줄임** | 앞부분이 비슷한 과목끼리 구분이 안 되면 필터를 잘못 고르게 됨. 예쁜 것보다 나쁜 문제 |
| 칩 **감싸기가 3~4줄 먹는다**는 주장 | 실측 결과 **수업 14개까지 2줄(96px)**. 가로 스크롤 대비 +42px뿐 |
| **히어로 숫자 타일**(236px) | 각 섹션 헤더 숫자와 완전 중복. 요약 문장도 첫 카드의 마감 타일과 중복. 타일의 고유 기능이던 '결과 바로가기'는 결과를 2번째로 올려 해소(결과 섹션 1645→1083px) |
| 우측 **'내 수업' 레일** | 수업 게시판이 없어 카드가 갈 곳이 없었음(죽은 핸들러). 필터로 대체하고 배지에 낼 과제 수를 얹음 |

**단, 히어로 타일은 올립이 되살릴지 재검토 중**이다(§6). 기각 논리의 약점: 섹션 헤더 숫자는 스크롤해야 보이므로, 같은 숫자라도 **보이는 시점이 다르면 역할이 다르다**.

   (파일 안 `#mockpick` 마크업은 이 스크립트가 대체하므로 그것만 고치면 안 나온다)
4. `<script src="mock_nav_dw.js?v=...">` 버전 올리기 (캐시)

### 필터 + 더 보기 (화면별 독립)
- 상태를 DOM에 얹어 시안끼리 안 섞이게 했다 — `root.dataset.f`, `sec.dataset.open`
- 섹션에 **`data-sec="todo|result|wait|soon"`** 필수. 없으면 계산에서 빠진다
- **`data-limit`** — 기본 5, `"0"`이면 전부 표시.
  ⚠️ 2026-08-11 사고: '더 보기' 버튼이 없는 섹션에 공통 상한이 걸려 6번째 카드가 영영 안 보였다. 버튼 없는 섹션엔 반드시 `data-limit="0"`
- 호출: 칩 `stFilter('c1', this)` / 드롭다운 `stFilter(this.value, this)` / 더보기 `stShowMore(this)`
- 수업 코드는 카드 안 `.sj` 클래스에서 읽는다. `.sj` 배지가 없는 행(제출 끝·곧 시작)은 **`data-sj="c1"`** 로 표기

### 수업 색·더미
- `.sj.c1`~`.c9` 9색 팔레트. 실제로는 **수업 순서대로 배정하고 넘치면 순환**. 배정 단위는 과목이 아니라 **수업**(같은 과목 2개면 다른 색이어야 구분됨)
- 더미 = **고교 선택과목 9개** (언어와 매체 / 현대사회와 미술세계 / 융합과학탐구 / 확률과 통계 / 영어권 문화 / 생활과 윤리 / 한국지리 / 세계사 / 미술 창작)
  긴 이름 검증용으로 일부러 고른 것. 국영수사과로 되돌리지 말 것
- 개수: 낼 과제 7 · 결과 6 · 제출 끝 4 · 곧 시작 2. **결과를 6으로 맞춘 이유** = 3열 카드 그리드가 3의 배수일 때만 마지막 줄에 구멍이 안 남
