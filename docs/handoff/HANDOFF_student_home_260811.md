## 2. 확정 정책 (올립 확정 — 시안 5도 이 정책을 따른다)

### 노출 원칙
학생에게 보이는 건 **선생님이 학생에게 "연" 것뿐**. 교사의 업로드·채점 활동은 결과 공개 전까지 학생 화면에 나타나지 않는다.

| 케이스 | 결과 공개 전 | 공개 후 |
|---|---|---|
| 교사 수거형 (학생 제출 안 엶) | **학생 홈에 아무것도 없음** | 결과 나온 과제 |
| 학생 제출형 · 온라인 제출 | 제출이 끝난 과제 | 결과 나온 과제 |
| 학생 제출형 · 종이로 내서 교사가 대신 업로드 | 제출이 끝난 과제 | 결과 나온 과제 |
| 교사가 결과를 공개하지 않음 | 그 자리 그대로, 채점 기색 없음 | — |

- 교사 수거형 비노출의 이유 = **선생님 혼자 클리포를 쓰는 사용 방식을 침해하지 않기 위함.** 이게 CLIPO의 원조 사용 방식이다.
- 학생 제출형은 **교사가 등록하면 즉시** '곧 시작하는 과제'에 노출(제출 시작일 안내). 상세 진입은 불가.

### 섹션 배치 규칙
- 마감 지남 + 아직 제출 가능 → **'지금 낼 과제' 맨 위** (정렬 = 남은 시간 오름차순, 지난 건 음수)
- 마감 지남 + 제출 불가 → **'제출이 끝난 과제'에 미제출 칩**
- 마감 없음 → '지금 낼 과제' 맨 아래

### 문구 원칙
- **"선생님 확인 중" 금지.** 결과 공개는 교사 선택이라 안 올 수 있다 → 지킬 수 없는 안내가 된다. 그래서 섹션명이 '제출한 과제'가 아니라 **'제출이 끝난 과제'**(미제출도 담기므로)이고, 설명은 "결과는 선생님이 **공개하면** 볼 수 있어요".
- **점수는 공개된 건에만** 표시. 교사가 `hide-score`로 끌 수 있음(`output/result_student_view_v3_260512.html`에서 확인). 비공개를 '비공개'라고 적지 않는다 — 박탈감만 준다.
- '제출 없이 채점' 같은 **교사 관점 용어 금지** → '선생님 등록'.

### 화면 구성 원칙
- 섹션 순서 = **학생 목적 순**: 지금 낼 과제 → 결과 나온 과제 → 제출이 끝난 과제 → 곧 시작하는 과제
  (상태 진행 순으로 두면 액션 없는 '제출이 끝난 과제'가 2번 자리를 차지함)
- **액션이 있는 것만 카드**(지금 낼 과제), 보기만 하는 건 행
- 모든 목록 섹션 **5개 + 더 보기**

### 필터 + 더 보기 (화면별 독립)
- 상태를 DOM에 얹어 시안끼리 안 섞이게 했다 — `root.dataset.f`, `sec.dataset.open`
- 섹션에 **`data-sec="todo|result|wait|soon"`** 필수. 없으면 계산에서 빠진다
- **`data-limit`** — 기본 5, `"0"`이면 전부 표시.
  ⚠️ 2026-08-11 사고: '더 보기' 버튼이 없는 섹션에 공통 상한이 걸려 6번째 카드가 영영 안 보였다. 버튼 없는 섹션엔 반드시 `data-limit="0"`
- 호출: 칩 `stFilter('c1', this)` / 드롭다운 `stFilter(this.value, this)` / 더보기 `stShowMore(this)`
- 수업 코드는 카드 안 `.sj` 클래스에서 읽는다. `.sj` 배지가 없는 행(제출 끝·곧 시작)은 **`data-sj="c1"`** 로 표기

### 수업 색·더미
- `.sj.c1`~`.c9` 9색 팔레트. 실제로는 **수업 순서대로 배정하고 넘치면 순환**. 배정 단위는 과목이 아니라 **수업**(같은 과목 2개면 다른 색이어야 구분됨)

  긴 이름 검증용으로 일부러 고른 것. 국영수사과로 되돌리지 말 것

  - **홈에 점수 싣지 않음** — 홈 역할은 '확인하러 가게' 하는 것. 점수를 미리 주면 확인 동기가 죽고, 점수 비공개 건과의 행 비대칭도 사라짐. 점수는 결과 상세·과제 탭 몫
  - **'곧 시작하는 과제' 홈에서 제거** — 라벨("곧 시작"은 주체가 안 보여 '내가 쓰기 시작'으로 오독) 검토 중 정체성이 드러남: 액션이 하나도 없는 항목이라 '처리하면 사라지는 인박스'인 홈과 상충. **과제 탭에는 유지**, '시작 전' 배지·상태 컬럼은 제거(섹션명+시작일이 같은 말이라 중복)
  - **수업 색 칩 → 일반 텍스트** (시안 5 한정) — 표·카드 모두. 색이 과제명보다 시선을 먼저 끌고, 9색 순환이라 색 자체가 의미도 없음. 필터용 수업 코드는 행/카드 `data-sj`로 이동(시안 3·4는 비교용이라 그대로)
  - **홈 2단 배치** — 곧 시작 제거로 홈이 '지금 낼 과제/새로 나온 결과' 두 축만 남음. 좌=행동·우=확인(1.25:1). 상하 배치는 결과가 항상 스크롤 아래로 밀려 존재 이유가 깎임
  - **'과제에서 모두 보기'는 '지금 낼 과제'에만** (카드 아래 전폭 버튼) — 두 섹션에 같은 링크를 달면 같은 곳으로 두 번 들여보내는 셈. **'새로 나온 결과'는 30일 안 안 본 결과를 전부 싣기 때문에 감춘 게 없어 링크 불필요**(10건을 넘지 않는다는 전제). ⚠️ 일관성의 기준은 형태가 아니라 **조건** — 조건이 다르면 UI가 달라도 된다(한 번 헤더 링크로 통일했다가 되돌린 건이므로 재론 방지)
  - **급함 신호 절제(A안)** — 빨간 날짜 타일·분홍 배경·분홍 테두리·파란 채움 버튼이 겹친 4중 인코딩이었고 5장 중 3장이 분홍이라 강조가 기본값처럼 보였음. **분홍 배경 제거 + 제출 버튼 전부 아웃라인 통일**, 신호는 날짜 타일에 몰아줌. 시안 3·4는 비교 대상이라 그대로(`#scr-home5` 오버라이드)

### 시안 5 과제 탭 — 단일 표 전환 (2026-08-11 올립)
섹션 4개(낼 과제/결과/제출 끝/곧 시작)를 **표 하나 + 상태 컬럼**으로 합쳤다.
- **이유**: 섹션 분할은 "마감 지남 + 제출 가능은 어느 섹션인가" 같은 분류 규칙을 매번 만들어야 했고, 한 과제가 두 섹션에 걸칠 여지(중복 노출)가 구조적으로 남았음. 찾는 행위는 필터·검색이 할 일이지 섹션이 할 일이 아님
- **상태 = '진행의 가장 최신 지점' 하나** (뒤 단계가 이김 → 배타적). 이게 이 설계의 핵심 전제:

  | 상태 | 뜻 | 색(의미) | 액션 |
  |---|---|---|---|
  | 낼 수 있음 | 지금 제출 가능(마감 지난 것 포함) | 주황 = 할 일 | 제출 |
  | 결과 나옴 | 결과 공개됨(제출 여부 무관) | 파랑 = 볼 것 | 결과 보기 |
  | 제출함 | 냈고 결과는 아직 | 초록 = 끝냄 | 답안 보기 |
  | 미제출 | 못 낸 채 마감, 결과 없음 | 빨강 = 놓침 | — |
  | 시작 전 | 제출이 아직 안 열림 | 회색 = 아직 | — |

  - '결과 나옴'이 '제출함'을 이기므로 결과 행에서 "내가 냈는지"가 안 보임 → **과제 정보 셀 하위 문구로 보완**(`7월 24일에 제출 · 7월 28일에 결과 공개` / `종이 답안을 선생님이 올렸어요` / `내지 못했어요`)
  - 기본 정렬 = 위 표 순서(할 일 → 새 결과 → 지난 것), 그 안에서 날짜순
- **검색 신설** — 과제명·수업명·선생님명(`tr[data-k]`에 소문자 키). 필터보다 앞에 둠(이름을 아는 과제가 가장 빠른 길)
- 필터 = 학기 탭 + 수업 + **상태**. 제출 상황 필터는 상태 필터로 흡수
- 구현: `t5Apply()` 한 함수가 검색·수업·상태를 함께 계산(따로 두면 서로 표시 여부를 덮어씀). 행은 `data-sj`(수업) · `data-st`(상태) · `data-k`(검색 키). 시안 3·4의 `stApply`와 무관하게 독립 동작
- **행 전체가 상세 링크** — 셀마다 다른 버튼(제출/결과 보기/답안 보기)을 두니 같은 위계인데 형태가 갈렸다. 마지막 칸은 **화살표 하나로 통일**, 호버도 행 단위. **'시작 전' 2행만 onclick·화살표 없음**(§2 상세 진입 불가 — 못 들어가는 곳에 들어갈 수 있는 표시를 두지 않는다)
- **날짜 = 행당 하나** — 한 행에 마감일·제출일·공개일이 최대 3개였음. 컬럼을 `날짜`로 재정의해 상태에 맞는 날짜 하나만 둔다(`~ 마감` / `~ 공개` / `~ 제출` / `~부터`). **마감 시간(16:00)은 '제출 가능' 행에만** — 지난 과제에 시간까지 알 이유가 없음
- **표 안의 색은 상태 배지 + 마감 급함(빨강) 두 가지만** — 전에는 파랑이 '안 본 결과'와 '쓰던 글' 두 뜻, 빨강이 '마감'과 '미제출' 두 뜻이라 색이 뭘 가리키는지 안 읽혔다. '쓰던 글이 저장돼 있어요'는 삭제(제출 화면 들어가면 바로 보임)
- **안 본 결과 = 과제명 앞 파란 점.** ⚠️ 배지 명도(채움형 진파랑)로 구분해 봤으나 **한눈에 안 들어와 점으로 되돌림**(2026-08-11 올립) — 재론 방지. 홈 '새로 나온 결과'에는 점을 붙이지 않는다(거긴 전 행이 안 본 것이라 정보량 0)
- **초등학생도 쓰는 화면이라 문구를 일상어로** (올립 지시): "마감 지남 · 아직 낼 수 있어요"→"늦었지만 아직 낼 수 있어요" / "종이 답안을 선생님이 올렸어요"→"종이로 낸 답을 선생님이 올려 주셨어요" / "전체 수업·전체 상태"→"모든 수업·모든 상태" / 검색 placeholder "과제나 수업 이름으로 찾아보세요" / 미제출·시작 전 행에 "이제 낼 수 없어요"·"이날부터 낼 수 있어요" 부연 추가.
  더미는 고교 선택과목 그대로 둔다(§4 — 긴 이름 검증용)
- **시안 2·4는 폐기 예정**(2026-08-11 올립) — 이후 작업은 시안 5만 신경 쓰면 됨
- **홈 카드 안에 버튼을 두지 않는다** — 카드가 이미 통째로 링크라 안쪽 버튼과 클릭 대상이 둘로 읽혔음. `제출하기 ›` / `이어 쓰기 ›` 텍스트+화살표로 바꿔 **과제 탭 행과 같은 문법**으로 통일. `쓰던 중` 칩도 제거(`이어 쓰기`가 같은 말)
