## 0. ⚠️ 먼저 읽을 것 — 오전 재설계는 회의로 되돌아갔다

같은 날 오전에 **설계(허브) + 과제 화면 만들기(전환 화면)** 2단으로 재설계했다가, 오후 회의에서 **인라인 유지로 되돌렸다.** §2는 그 결정을 반영한 최종본이고, 아래 §2-0이 회의 결정이다.

### 2026-08-28 회의 결정 (최종)
- **학기 중이므로 변경사항을 줄여 inline으로 진행.** 현재 사용자는 **PDF 일괄 업로드가 중심**이고, 학생 직접 제출 설정을 별도 페이지로 빼면 **목록 페이지를 테이블 UI로 전환해야 해서** 변경 폭이 커진다.
  → **별도 페이지 분리는 2027학년도 1학기 목표로 겨울에 개선(윈터 백로그).**
- **학생 과제 미리보기 등 추가 기능은 추후 고려** → 이번에 만든 우측 미리보기 패널 제거.
- **마이그레이션 문항은 `답안을 입력해 주세요.` 라는 문항 내용으로 적용.**
  ⚠️ 이 결정으로 **'빈 문항' 상태가 사라진다** — v0.4의 "이전된 기존 과제만 빈 내용 허용" 예외가 없어지고, 목록의 `문항 미작성` 배지도 뜰 경로가 없다. PRD 개정 시 함께 정리할 것.
- **권장 글자 수는 비어 있을 수 있음** — 없으면 0자로 저장, 있으면 1자 이상.
- 유지: **AI 채점 조건 등 하늘색 UI를 덜어낸 개선은 피그마보다 나으므로 그대로 간다**(올립). → §2-5 안내 위계.

## 1. 지금 상태 한 줄

평가 설계는 **한 페이지 인라인**이다. 제출 방식·문항·기간·안내가 모두 `학생 직접 입력 또는 제출 : 제출 방법 설정` 섹션 안에 있고, 저장은 하단 `설계 저장` 하나뿐. PRD v0.4와의 차이는 **마이그레이션 문항 내용**과 **권장 글자 수 선택제** 두 건 → 개정 필요(§6).

## 2. 구조와 근거

### 2-1. 큰 구조 — 한 페이지 인라인

```
평가 설계 (한 페이지 · 세로 스크롤)
① 기본 정보
② 성취기준 · 채점기준(+AI 생성 드로워) · 점수 산출 방법
③ 과제물 업로드 방법 3카드
   ├ 선생님 직접 일괄 업로드 → 준비 팁 박스(.next-box)
   ├ 학생 직접 입력 또는 제출 → 아래 섹션이 펼쳐짐
   └ 과제물 없이 바로 채점 → 아무것도 없음
④ 학생 직접 입력 또는 제출 : 제출 방법 설정   ← 학생 직접일 때만
   1. 과제 안내 (선택)
   2. 제출 방식 및 설정
      ├ 클리포에서 직접 작성 → **문항 목록을 여기서 바로 씀(인라인)** + 작성 환경
      └ 파일 제출 → 허용 파일 형식 · 최대 제출 파일 수
   3. 제출 기간
하단: 임시 저장 / 설계 저장   ← 저장은 이것 하나뿐
```

- **스텝바(위저드) 없음.** 교사에게 이건 단계가 아니라 한 과제의 여러 면이고 서로 참조하며 오간다(올립). **인터뷰상 작성 순서가 사람마다 다르다** — 채점기준 먼저 쓰는 교사도, 문항 먼저 쓰는 교사도 있다. 순서를 강제하지 않고 **완성 검사는 저장 시점에만** 건다.
- 카드 순서(기준 → 과제)는 평가 설계 정석이자 현행 개발 화면과 같아 재학습 비용이 없다.
- **HIAI 평가 설계 시안과의 일관성은 의도적으로 맞추지 않았다**(올립: HIAI 미확정이니 교사 니즈로만).

### 2-2. 왜 별도 페이지가 아닌가 (윈터 백로그로 넘긴 이유)

오전에 "학생이 보는 콘텐츠 vs 교사만 보는 설정"으로 갈라 전환 화면을 만들었고, 그 과정에서 얻은 결론은 살려 둘 만하다 — **제출 방식은 교사 설정처럼 보이지만 학생 화면의 답 입력 영역을 그대로 결정한다**(직접 작성=에디터 / 파일 제출=업로드 칸). 그래서 분리한다면 제출 방식까지 통째로 가져가야 한다.

다만 **지금은 분리하지 않는다** — 학기 중 변경 최소화, 현재 사용자는 PDF 일괄 업로드 중심, 분리 시 목록 페이지를 테이블 UI로 전환해야 함(§0). **2027-1학기 목표로 겨울에 재개.**

### 2-3. 문항은 직접 제출 전용이 아니다

출력→오프라인 손글씨→스캔(교사 일괄 업로드)도 가능하다(올립). **내년 "문항 탭"(AI 문항 생성)으로 독립 예정.**
단 **올해 정책은 좁게 유지** — 문항은 직접 작성을 켠 과제 안에서만 쓴다.

### 2-4. 준비 팁 박스(`.next-box`)

`선생님 직접 일괄 업로드`를 고르면 수집 방법 카드 아래 준비 팁 박스가 뜬다(아이콘 타일 + 제목 + 부제 + outline 버튼 → 팝업).
`.next-box`는 오전에 두 후속(준비 팁 / 과제 화면 진입)을 같은 그릇으로 맞추며 만든 컴포넌트인데, 인라인 복귀로 **지금은 준비 팁 하나만 쓴다.** 분리를 재개할 때 그대로 재활용할 수 있다.

### 2-5. 안내 문구 위계 — **다른 목업에도 적용할 룰**

두 번 뒤집혀 나온 결론. 상세는 `docs/design-system.md` "안내 문구 위계", 메모리 `feedback_notice_hierarchy`.

| 단 | 언제 | 모양 |
|---|---|---|
| 상시 설명 | 늘 있는 필드 설명 | `.sec-desc` 회색 14px |
| **조건부 안내** | 조건 맞을 때만 뜨고 막지 않음 | **`.note`** — 박스 없이 파란 `info` 아이콘 + 본문색 |
| 경고·잠금 | 되돌릴 수 없거나 동작 제한 | `.alert-info warn` 주황 박스 |

- 파란 인포 박스(`.alert-info` 기본형)는 **쓰지 않는다.**
- 조건부 안내를 회색 보조 문구로 두면 **상시 설명과 구별이 안 돼 눈이 걸러낸다** — 이게 두 번째 지적의 원인이었다.

### 2-6. 그 밖에 확정된 것

- **활동지 탭은 제품에 안 들어간다**(올립) — 목업 전용이라 폐기. 내년 "문항 탭"으로 대체.
  이 파일 탭 밴드에서 제거 완료. `HANDOFF_hiai_eval_design_port_260826.md` §2-2도 갱신(충돌 해소).
- **④ AI 채점 지침 (선택)** — 라벨 확정. "도움 자료"는 *AI가 만들어 준다*로 오독되는데 방향은 **교사→AI**(빈 활동지·모범답안·채점 가이드를 준다). 내용은 HIAI 것 재사용 가능. **10월 예정, 이번 목업 제외.**
- 파일 제출을 켜면 **허용 파일 형식은 PDF·이미지가 기본 체크**. 기타 파일(HWP 등)을 체크하면 조건부 안내.
- 저장 확인 팝업 — `계속 작성` 제거 후 **우측 상단 X**로, 버튼은 **`저장 안 하고 나가기` / `저장 후 나가기`**.
  ⚠️ CLIPO `버튼은 단어형·"~하기" 금지` 규칙의 **의도적 예외**다. 둘 다 화면을 떠나므로 `저장`만으로는 남는지 나가는지 알 수 없다. 되돌리려면 올립 확인 후.
- 섹션 제목 아래 여백 **16px**(`.sec-hd` 기본 6px은 설명문이 있을 때 값). 답답하다는 지적을 두 번 받고 올린 값이니 낮추지 말 것.

## 3. 파일에 실제로 바뀐 것

`output/task_direct_write_v1_260729.html` — **씬은 `scr-design` / `scr-list` 둘뿐이다.**

- 문항이 `way-write`의 `way-body` 안에 인라인으로 들어감(`#q-list`). 문항 수는 `문항 (N개 / 20개)`.
- **권장 글자 수 = 체크박스(`.cbx`) + 스테퍼.** 끄면 `0`(없음), 켜면 기본 500. 새 문항은 **기본 꺼짐**. 범위 1~5,000(±100 스텝).
- 마이그레이션: `applyDesignState(0,{migrated:true})` → 문항 1개, 내용 `답안을 입력해 주세요.`(`Q_MIGRATED`). 목록 카드도 `이전된 과제` 태그로 교체.
- 안내 위계 유지: `.note`(조건부 안내) — `way-none` · `way-both` · `multiFileNote` · `attachFmtNote` · `fmtNote`. warn 박스는 `waysLockNote` · `lockNote` 둘뿐.
- 허용 파일 형식: 파일 제출을 켜면 PDF·이미지 기본 체크, 기타 파일 체크 시 조건부 안내(`toggleFmt`/`syncFmtNote`).
- `applyDesignState()` : 수집 방법(`opt.method`)·허용 파일 형식·작성 환경까지 카드마다 리셋.
- `updateSummary()` : 요약 박스가 없어져 **목록 배지 갱신만 하는 얇은 함수**로 남김(호출부가 많아 이름 유지).
- 제거: `scr-questions` 씬, `.tw-*`·`.sp-*`·`.qdw*`·`.qprev*`·`.tip-bar*` CSS, `renderStuPrev`/`prevPeriodText`/`addPrevAttach`/`syncTaskScreen`/`goQuestions`/`leaveQuestions`/`saveQuestions`/`qGuard*`/`Q_SNAP`.
- 까망이(`mock_nav_dw.js`) : **교사/학생 2탭** 유지, `dwQuestions` 라우트 제거. 캐시 `?v=260828c`.

### 이번에 고친 버그
1. `직접 작성` 켜면 문항 1개가 생기는데 요약이 `작성한 문항 없음`으로 남던 것(요약 박스 자체가 없어져 해소).
2. **`선생님 업로드 평가` 카드가 학생 직접 제출로 열리던 것** — 수집 방법을 안 넘겨 앞 카드 값이 남음 → `opt.method` 추가.
3. 목록 카드가 배지와 다른 상태로 열리던 것 → `withQ`/`migrated`를 카드마다 명시.

## 4. PRD

**[C-2608 학생 직접 제출 개선](https://app.notion.com/p/3ac17e5c8cf181acbd5be82063820274) — v0.4가 최종.**

⚠️ **v0.1~v0.3은 지우지 말 것.** 코멘트 13건이 그 블록들에 앵커돼 있어 `replace_content`로 갈아엎으면 날아간다. 수정은 항상 `update_content` 부분 수정으로.

### 확정 정책 (v0.4 — 옛 값 쓰지 말 것)

- **문항 번호 입력란 없음.** 화면의 `문항 1`·`문항 2`는 순서 표시용 시스템 값. `1-1`, `가` 같은 표기는 교사가 **문항 내용 안에** 직접 씀
- **문항 내용 1글자 이상 필수.** 빈 문항 있으면 설계 저장 불가. 예외는 **이전된 기존 과제**뿐
- 직접 작성을 켜면 **문항 1개 자동 생성** → 문항 0개 상태·`준비 중` 학생 화면 없음
- 문항 1~20개, 추가 순서 고정(재정렬 없음), 문항 내용 최대 1,000자
- **권장 글자 수**(문항별) — 넘어도 입력·제출 가능, 학생 화면 글자 수만 빨강. 시스템 상한 5,000자
- **제출 후에도 문항 추가·수정·삭제 가능.** 삭제는 `제출 1명 이상`이면 확인 1회 (**임시 저장만 한 학생은 인원에 안 셈**)
- **삭제된 답안** = 학생 화면에 **내가 쓴 글이 그대로 보이고** 문항 옆 `삭제된 답안` 배지 + 입력 불가.
  제출했던 글이든 임시 저장이던 글이든 **같은 모양**(분기 없음). 교사 채점·결과 공개 화면엔 미표시
- **화면을 켜둔 사이 문항 구성이 바뀌면** 제출·임시 저장 클릭 시 안내 + 새로고침 유도 (삭제 정책과 **별개**)
- **제출 방식 해제 = 확인 후 허용.** 이미 낸 답안은 문항 삭제와 같은 규칙으로 보존.
  단 제출 1건 이상이면 **마지막 남은 방식은 못 끔**
- **결과 공개 후 재제출 = 불가.** 결과 공개되면 학생은 그 뒤로 결과 공개 화면만 봄
- **수동 마감이 `마감 후 제출 허용`을 이김**
- 채점 후 재제출 **별도 안내 안 함**(엣지케이스) · 답안 다운로드 **PDF 단일**
- 교사 채점 화면에 **문항별 작성 글자 수 표시**
- **교사는 임시 저장을 전혀 못 봄** — `작성 중 · N자` 표시도 없음. 그냥 `미제출`
- 기존 과제 이전 = **문항 1개(내용 빈 상태)**, 학생 답안은 그 문항에 그대로

## 7. 작업 시 주의

- **미리보기 서버 좀비** — `preview_start`가 3457을 못 잡고 다른 포트로 밀린 뒤 그 포트도 응답 안 하는 일이 잦다.
  `Get-NetTCPConnection -LocalPort 3457 -State Listen`로 PID 찾아 `Stop-Process`. 2026-08-28에 3개가 물려 있었다.
- **브라우저 캐시가 세다** — HTML 자체가 캐시돼 수정이 안 보인다. `?cb=n` 쿼리를 붙여 확인할 것.
- **공용 JS(`mock_nav_dw.js`)를 고치면 `?v=`를 올린다** — 6개 파일 전부.
- **파이썬 일괄 수정 스크립트는 실패하면 전체가 저장 안 된다** — 실패 시 무엇이 저장됐는지 grep으로 확인부터.
- 구글드라이브 위 git이라 커밋 후 수 분 멈출 수 있다(`gc.auto 0`로 완화). **타임아웃=실패 아님, `git log`로 확인.**
