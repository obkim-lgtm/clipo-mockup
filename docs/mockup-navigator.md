# 목업 내비게이터(까망이) 규칙

시연용 다크 플로팅 패널. 제품 UI가 아니라 **목업을 보여주기 위한 도구**다.
새 목업을 만들 때나 기존 목업에 케이스를 추가할 때 이 규칙을 따른다.

구현체: `#mockNav` (output/*.html 하단 "목업 내비게이터(까망이)" script 블록).
현재 삽입 파일: `task_ocr_v3` · `class_scoring_detail_v3` · `scoring_elementary_v3` ·
`scoring_survey_v1` · `scoring_secondary_v1` · `scoring_secondary_current_v1`
(확인: `grep -l mockNav output/*.html`)

## 1. 목업 도구는 하나, 어느 화면에서도 나갈 수 있어야 한다

- **어떤 화면에서도 까망이를 숨기지 않는다.** 특정 화면에서만 뜨는 전용 패널을
  따로 만들지 않는다.
- 화면별 케이스 선택기가 필요하면 전용 패널이 아니라 **까망이 안의 케이스 그룹**으로 넣는다.

> 왜: 여러 파일 일괄 업로드 화면이 전용 패널(`#bmCase`)을 띄우고 까망이를 숨겨,
> 그 화면에 들어가면 다른 화면으로 나갈 길이 없었다(2026-07-29 정리). 같은 성격의
> 상세인데 설문 화면과 도구가 달라 보이는 문제도 함께 발생했다.

## 2. 진입 항목 → 그 화면에서 케이스 그룹으로 펼친다

| 위치 | 까망이에 보이는 것 |
|---|---|
| 목록·상위 화면 | 상세로 가는 **진입 항목 1개** (예: `설문 일괄 업로드`) |
| 그 상세 화면 | **같은 이름의 그룹**이 케이스 목록으로 펼쳐짐 (정상 + 실패·변형 케이스) |

- 케이스 그룹이 펼쳐진 화면에서는 **진입 항목을 숨긴다** — 같은 라벨이 두 번 보이지 않게.
- 구현: 그룹에 `showOn:[케이스 route 배열]`, 진입 항목에 `{hideOnCur:같은 배열}`.

```js
var SURVEY_CASES = ['uploadSurvey','surveyFormat','surveyMatch','surveyOver'];
{ t:'학급 일괄업로드 팝업', ctx:'task', items:[['uploadSurvey','설문 일괄 업로드',{hideOnCur:SURVEY_CASES}]] },
{ t:'설문 일괄 업로드', ctx:'task', showOn:SURVEY_CASES, items:[['uploadSurvey','정상'], ...] },
```

## 3. 모든 케이스는 딥링크 + 활성 표시

- 케이스마다 고유 URL을 준다: `?nav=<화면>&case=<케이스>`
  (예: `?nav=uploadBulk&case=ambig`). 새로고침·링크 공유로 같은 화면이 복원돼야 한다.
- **지금 보고 있는 케이스가 파랗게 활성 표시**돼야 한다. 화면 상태가 바뀌면
  (케이스 전환·모달 오픈) 활성 표시도 같이 갱신한다 — CLIPO는 `syncDemoNavs()`가 담당.
- 화면 자체의 해시 라우팅 규칙은 [workflow.md](workflow.md) '화면마다 고유 URL'을 따른다.

## 4. 라벨·표시

- 그룹 안 라벨은 **평행하게**(정상 → 실패 케이스 순, 어미·형태 통일).
- 부제가 필요하면 `{sub:'…'}` — 11px 보조색, 줄바꿈 허용. **가로 스크롤 금지.**
- 진입 항목 라벨은 서로 평행하게(`여러 파일 일괄 업로드` / `설문 일괄 업로드`).
- **실제로 쓰지 않는 도구 버튼은 넣지 않는다** (예: 케이스 리셋 — 2026-07-29 제거).

## 5. 여러 파일에 공통 삽입된다 — 한 파일만 고치지 말 것

- ROUTES·GROUPS·CSS·render 블록은 삽입된 모든 파일에서 **동일**해야 한다.
  한 파일에서만 라벨을 바꾸면 화면을 옮길 때 까망이가 달라 보인다(실제로 발생).
- 일괄 수정은 [workflow.md](workflow.md) '변경 영향 범위' 절차를 따른다
  (문자열 리터럴 치환 + 치환 건수 검증 + 백업).

## 6. 기본 사양 (건드리지 말 것)

- 우하단 다크 플로팅 · 드래그 이동 · 헤더 클릭으로 접기 · 위치와 접힘 상태는
  localStorage로 파일 간 유지.
- 컨텍스트(탭)별로 해당 그룹만 노출(`ctx:'task'|'scoring'`), 헤더에 `MOCKUP · <컨텍스트>` 표기.
- 제품 UI가 아니므로 화면 캡처·시연 외 기능(데이터 조작 등)은 넣지 않는다.
