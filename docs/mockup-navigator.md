# 목업 내비게이터(까망이) 규칙

시연용 다크 플로팅 패널. 제품 UI가 아니라 **목업을 보여주기 위한 도구**다.
새 목업을 만들 때나 기존 목업에 케이스를 추가할 때 이 규칙을 따른다.

구현체는 두 갈래다. **새 목업은 공유 파일 방식(B)을 쓴다.**

| 방식 | 구현체 | 삽입 파일 |
|---|---|---|
| A. 파일 내장 (기존) | 각 HTML 하단 `#mockNav` script 블록 | `task_ocr_v3` · `class_scoring_detail_v3` · `scoring_elementary_v3` · `scoring_survey_v1` · `scoring_secondary_v1` · `scoring_secondary_current_v1` |
| B. 공유 파일 (권장) | `output/mock_nav_dw.js` 하나 | `task_direct_write_v1_260729` · `focus_log_v1_260728` · `scoring_direct_write_v1_260729` · `student_home_v1_260729` · `student_submit_v1_260729` |

확인: `grep -l mockNav output/*.html` · `grep -l mock_nav_dw output/*.html`

B가 §5(전 파일 동일해야 함)를 구조적으로 보장한다 — 라벨·그룹을 공유 파일 한 곳만 고치면 된다.
A로 된 기존 세트는 그대로 두고, 손볼 일이 생기면 그때 B로 옮긴다.

## 0. 공유 파일 방식(B) 붙이는 법

각 HTML에 두 군데를 넣는다.

**① `<head>` 맨 앞** — 진입 해시 보존:
```html
<script>window.MOCK_NAV_ENTRY_HASH = location.hash;</script>
```
> **반드시 필요하다.** 목업 대부분이 `</body>` 직전에 `go(location.hash…)` 같은 초기화를
> 두는데, 이게 까망이보다 먼저 돌면서 **모르는 해시를 자기 기본 화면으로 `replaceState` 해버린다.**
> 그러면 딥링크(`#result-after` 등)가 통째로 씹힌다. head에서 원본 해시를 먼저 잡아둬야 한다.

**② `</body>` 직전** — 파일 키 + 케이스 핸들러 + 스크립트:
```html
<script>
window.MOCK_NAV_FILE  = 'submit';                    // mock_nav_dw.js 의 FILES 키
window.MOCK_NAV_APPLY = {                            // route → 이 파일 안에서 그 케이스를 적용
  ssWrite: function(){ go('write'); },
  ssAfter: function(){ go('done'); setOpened(true); }
};
(function(){                                          // 화면 안에서 이동해도 활성 표시가 따라오게
  var MAP = { write:'ssWrite', done:'ssDone' };
  var _go = window.go;
  if (typeof _go === 'function') window.go = function(s){
    _go.apply(this, arguments);
    if (window.mockNavSetCurrent && MAP[s]) window.mockNavSetCurrent(MAP[s]);
  };
})();
</script>
<script src="mock_nav_dw.js?v=260806a"></script>
```

- 공유 JS를 고치면 **`?v=` 를 올린다** (루트 CLAUDE.md 캐시 규칙). 안 올리면 구버전이 캐시에서 로드돼
  "고쳤는데 그대로"가 된다 — 실제로 겪음.
- 딥링크 적용은 `load` 이후에 돈다(페이지 초기화보다 뒤에 와야 하므로). 패널 자체는 즉시 그려진다.
- 구형 패널(`#mockpick`·`#mockjump`)·화면 전용 토글은 공유 CSS가 `display:none`으로 덮는다 — 마크업은 남겨둔다.
  **구형 패널 id가 새로 나오면 공유 JS의 숨김 목록에 추가한다** — 빠지면 까망이가 두 개로 보인다(2026-08-06 `#mockjump`로 실제 발생).

## 1. 목업 도구는 하나, 어느 화면에서도 나갈 수 있어야 한다

- **어떤 화면에서도 까망이를 숨기지 않는다.** 특정 화면에서만 뜨는 전용 패널을
  따로 만들지 않는다.
- 화면별 케이스 선택기가 필요하면 전용 패널이 아니라 **까망이 안의 케이스 그룹**으로 넣는다.

> 왜: 여러 파일 일괄 업로드 화면이 전용 패널(`#bmCase`)을 띄우고 까망이를 숨겨,
> 그 화면에 들어가면 다른 화면으로 나갈 길이 없었다(2026-07-29 정리). 같은 성격의
> 상세인데 설문 화면과 도구가 달라 보이는 문제도 함께 발생했다.

## 2. 전체 화면·케이스를 항상 펼쳐 둔다 (2026-08-06 개정)

- **모든 그룹·케이스를 상시 노출**하고, 길이는 패널 내부 스크롤로 처리한다.
  하위 케이스 그룹은 `└ ` 접두어로 상위 화면 아래에 들여 쓴다.
- 구버전 규칙(해당 화면에 들어가야 케이스 그룹이 펼쳐짐 — `showOn`/`hideOnCur`)은 폐기.
  어떤 케이스가 있는지 자체를 알 수 없어 "차트가 없다"처럼 **못 찾는 일**이 실제로 생겼다.
- 케이스 버튼을 누르면 해당 파일·해시로 딥링크 이동하고 그 케이스가 적용된 채 열린다.

## 3. 모든 케이스는 딥링크 + 활성 표시

- 케이스마다 고유 URL을 준다: `?nav=<화면>&case=<케이스>`
  (예: `?nav=uploadBulk&case=ambig`). 새로고침·링크 공유로 같은 화면이 복원돼야 한다.
- **지금 보고 있는 케이스가 파랗게 활성 표시**돼야 한다. 화면 상태가 바뀌면
  (케이스 전환·모달 오픈) 활성 표시도 같이 갱신한다 — CLIPO는 `syncDemoNavs()`가 담당.
- 화면 자체의 해시 라우팅 규칙은 [workflow.md](workflow.md) '화면마다 고유 URL'을 따른다.

## 4. 라벨·표시

- 그룹 안 라벨은 **평행하게**(정상 → 실패 케이스 순, 어미·형태 통일).
- 부제가 필요하면 `{sub:'…'}` — 11px 보조색, 줄바꿈 허용. **가로 스크롤 금지.**
- 진입 항목 라벨은 서로 평행하게(`여러 파일 일괄 업로드` / `설문 일괄 업로드`).
- **버전·신규 표시를 넣지 않는다** (예: `v2 신규 · 모달`). 목업 이력이지 리뷰어에게
  필요한 정보가 아니다. 부제는 케이스 성격 설명에만. (2026-08-06)
- **실제로 쓰지 않는 도구 버튼은 넣지 않는다** (예: 케이스 리셋 — 2026-07-29 제거).

## 4-1. 모달을 여는 케이스도 라우팅 안으로 (2026-08-06)

까망이 버튼에 `onclick="openXxxModal()"`을 **직접 물리지 않는다.** 한꺼번에 세 가지가 깨진다.

- **케이스 전환 시 "열려있는 모달 닫기" 처리에 신규 모달을 반드시 포함한다.**
  빠뜨리면 모달을 띄운 채 다른 케이스를 눌러도 **모달이 그대로 덮여 있어** 화면이
  바뀐 걸 못 본다. 까망이 z-index가 오버레이보다 높아 클릭은 되므로 더 헷갈린다.
- 그 상태에서 같은 모달 버튼을 다시 누르면 이미 열려 있어 아무 변화가 없고,
  **"버튼이 안 눌린다"로 보고된다.** 원인은 버튼이 아니라 위 항목이다.
- 케이스로 편입하면 활성 표시·딥링크·재오픈이 함께 따라온다. 화면 전환 없이
  모달만 여는 케이스는 `history.replaceState`로 자기 URL을 유지한다 — 화면 전환
  함수가 URL을 덮어쓰기 때문.
- HIAI 동일 규칙: `hiai_mockup/docs/mockup-navigator.md` §4-1.

## 5. 여러 파일에 공통 삽입된다 — 한 파일만 고치지 말 것

- ROUTES·GROUPS·CSS·render 블록은 삽입된 모든 파일에서 **동일**해야 한다.
  한 파일에서만 라벨을 바꾸면 화면을 옮길 때 까망이가 달라 보인다(실제로 발생).
- 일괄 수정은 [workflow.md](workflow.md) '변경 영향 범위' 절차를 따른다
  (문자열 리터럴 치환 + 치환 건수 검증 + 백업).

## 6. 기본 사양 (건드리지 말 것 · 2026-08-06 개정)

- **좌하단** 다크 플로팅 · 드래그 이동 · 헤더 클릭으로 접기 · 위치·접힘 상태는
  localStorage로 파일 간 유지 (위치 키 `clipoMockNavPosL` — 기본 위치를 바꿀 땐
  키를 갈아 예전 저장값이 새 기본을 덮지 않게 한다).
- **높이는 화면의 절반(50vh)까지만, 목록은 내부 스크롤.** 헤더는 스크롤과 무관하게 고정.
  스크롤 위치는 재렌더·파일 이동에도 유지한다(localStorage `clipoMockNavScroll`).
- **구형 패널(`#mockpick`·`#mockjump`·`#rubDemoToggle`)은 CSS 숨김 + DOM 제거 둘 다** —
  CSS만으로는 캐시·id 누락 시 까망이가 두 개로 보이는 사고가 재발했다(2026-08-06 ×2회).
  새 구형 id가 생기면 공유 JS의 제거 목록에도 추가.
- 헤더에 `MOCKUP · <세트명>` 표기.
- 제품 UI가 아니므로 화면 캡처·시연 외 기능(데이터 조작 등)은 넣지 않는다.
