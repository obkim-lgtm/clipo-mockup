`output/rep_teacher_succession_v1_260731.html` 정비 → 배포. 노션 PRD `소속 변경 안내 메시지 강화` 재구성.

## 결정된 것

**정책은 현행 유지.** 소속 해제 시 데이터 처리(보관·파기)를 바꾸지 않기로 확정.
"해제당한 교사에게 30일 다운로드 창을 주자"를 검토했으나 접음 — 다운로드는 열람보다 강한 처리(통제 밖 복제)라, 열람을 막는 근거와 정면으로 충돌한다. 대신 **개인 산출물(평가계획·채점기준)과 학생 식별 자료를 나누는 방향**이 맞다고 정리해 두었으나 이번 범위는 아님.

**과업을 끊어서 배포.** 이번 = 화면 안내 강화만 / 후속 = 데이터 보관·안내 메일·만료 안내·일괄 내보내기.
근거는 CS 실측 — 열람 불가 불만 12건 vs 대표교사 인계 부재 47건. 큰 덩어리부터 친다.

## 목업 변경

- **학교 설정 › 선생님 목록**을 개발 화면 구조로 교체 (서브탭·권한 필터·컬럼). `docs/design-system.md` 개발 화면 기준 표에 등재
- `[삭제]` → `[소속 해제]`, 권한 배지(대표교사/일반교사/인증 대기) 도입
- 대표 맡기 확인 모달 신규, 소속 변경 1단계에 확인 체크박스 게이트 추가
- 실행 확인 모달을 **권한 무관 공통 문구**로 통일 (승계 대상은 결과 토스트로)
- 실행 후 이동: 내 정보(미인증) → **교사 인증 화면**
- 해제당한 교사 행을 목록에 남기지 않고 즉시 제거
- 후속 범위(보관·재인증 복구·안내 메일) 문구를 모든 안내에서 제거
- 까망이 14항목 → 9항목. 제거한 케이스의 죽은 코드(현재 동작 모달·A/C 시나리오 분기·라우팅 항목)까지 정리

## 문구 원칙으로 굳힌 것

- **제품이 못 하는 대안을 제시하지 않는다.** "대표교사께 요청하세요"를 넣었다가 뺌 — 자료 이관 기능이 없어서 지킬 수 없는 안내였다. "어렵다"까지만 말하고 대안을 지어내지 않는다
- **이번 배포에 없는 기능을 안내에 약속하지 않는다.** 보관 기한·재인증 복구·메일 발송이 후속으로 빠지면서 관련 문구를 전부 걷어냄
- **경고 박스가 곧 부스럼이 되기도 한다.** "여러 학급 일괄 다운로드 없음" 경고를 중립 리드문으로 교체. 결함 고백이 아니라 확인 요청으로
- 상세는 `docs/workflow.md`, 용어·권한은 `docs/design-system.md`

## 정정한 사실 오류

- **"학생 계정을 등록하거나 삭제"는 오기** — 등록은 전 교사, 삭제만 대표교사. 목업 4곳 정정
- `대표 선생님` → **`대표교사`** 전수 교체
- PRD의 목업 해시(`#rep1-1` 등)가 존재하지 않는 앵커였음 → 실제 값으로 교체

## PRD 재구성

정책 검토(토글)와 개발 범위(본문)를 분리. 토글 4개 → 2개.
본문은 `# | 무엇을 바꾸는가` 2열 + 개조식으로 축약하고, 화면·문구 상세는 피그마 기획서로 넘김.
이미 구현된 것(목록 필터·인증 대기 비활성·최근 활동/인증일)과 정책 미정인 것(삭제 건수 표기)을 범위에서 제거 → A 6건 · B 5건 · 논의 필요 1건.

작성 기준은 `../prd_guide.md` §4 서술 수준에 반영.
